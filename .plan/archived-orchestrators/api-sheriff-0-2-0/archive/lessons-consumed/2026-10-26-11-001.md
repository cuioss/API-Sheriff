# A latch or barrier release does not start racing threads together, so a race test needs a vacuity control, an adaptive round count and a mutation check

Source: PLAN-V02-04 (#521), lessons-capture step; fix in #522 (`e087e5ce`).

## Observation

`EdgeAdmissionTest`'s admit/drain race test failed its own vacuity control on a loaded merge-queue runner (run 40292535629): 0 of 100 rounds admitted, so the race was never exercised and the test proved nothing. Both race threads were released from a `CountDownLatch`. `countDown()` wakes the waiters one by one, so on a loaded runner the drain thread ran its whole round before the admitting thread was scheduled.

The same PR's push run then failed `GatewayCookiesTest.shouldCompareConfiguredNameCaseSensitively` for a related reason: a generated input (the "different case" variant of a generated name) could equal the original when the generator drew an all-uppercase remainder. A test whose negative case depends on a random draw needs a variant that always differs.

## Rule

- A latch or barrier release is not a simultaneous start. Release race threads through a spin barrier so both are already running when a round starts.
- Measure whether the race was exercised (a vacuity control), and size the round count adaptively (run until enough rounds exercised the race, with a cap), not as a fixed number.
- After any change to the release mechanism, show with a mutation that the test still catches the bug it targets. A head-start variant tried first fixed the vacuity and missed the flag-first mutation 3 of 3 times.
- A "different" variant derived from a generated value must be constructed to differ (invert every letter), not drawn.

## Apply

Any new race test in `edge/` (`EdgeAdmissionTest`, the drain and retirement tests) and any test that builds a negative case from the generator.
