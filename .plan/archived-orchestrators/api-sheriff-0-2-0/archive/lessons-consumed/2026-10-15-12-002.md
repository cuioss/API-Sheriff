# A timing race in a refactored concurrency test showed only on a 2-core CI runner

Source: kidicap-gateway-requirements PLAN-32 (PR #466), ci-verify loop-back TASK-011 (findings bba03b / 1c4be8).

## What happened

`GatewayEdgeEarlyResponseResetTest` passed locally and failed in CI on a 2-core runner. The first diagnosis treated the gateway-side view and the stub-side view of the upstream as one thing, which pointed toward a gateway change that was not needed. Once the two views were separated, the fault turned out to be the test's own wait condition, and the fix stayed in the test.

## Rule

1. Before pushing a test with concurrency or timing assertions, also run it locally at low parallelism (`-XX:ActiveProcessorCount=1` or `2`).
2. Assertion messages and diagnostics in such tests report the gateway-side view and the stub-side view separately, so a CI failure says which side's expectation broke.
