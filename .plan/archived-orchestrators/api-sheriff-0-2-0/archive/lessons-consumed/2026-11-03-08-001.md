# A POM-wiring guard that answers 'will Maven run this execution?' must state every run condition up front, or review adds them one per round

Source: PLAN-V02-55 (#558), finalize automatic-review.

## Observation

The plan wrote `ComposeFixtureImageBuildWiringTest`, a guard that reads `integration-tests/pom.xml` and asserts that every stack-starting profile builds its fixture images before the stack starts. The first version matched the build by its arguments. CodeRabbit re-reviewed after every fix push, and each round named one more condition under which Maven would not actually run the matched execution:

1. an execution carrying the build arguments but no `exec` goal;
2. a copy of Maven's lifecycle inside the test, an execution bound to no phase, and `<skip>true</skip>`;
3. a misspelled phase (`pre-integration-tset`), which Maven silently never runs.

Each round was valid and each cost one full fix cycle: edit, pre-push quality gate, push, re-review — about 45 minutes of gate time, four cycles in total, for a test the plan itself had authored.

## Rule

When a test answers "will Maven run this execution, before that one?", write the full run predicate in the first version, not the arguments match alone:

- bound to the expected goal (`<goals><goal>exec</goal></goals>`);
- bound to the exact phase the consumer uses, compared by equality with that one phase name — not a membership test against a hand-copied lifecycle list, which reviewers flag as a mirror and which still accepts other phases;
- not disabled (`<configuration><skip>true</skip>`);
- declared before the dependent execution when both share a phase (Maven runs one plugin's executions of one phase in declaration order).

Give each condition a negative specimen in a table-style test (other phase, no goal, no phase, after the start, skipped, start skipped, misspelled phase), so a reviewer sees the whole predicate covered in one round.

## Apply

Any plan that adds or changes a structural guard over `pom.xml` wiring (exec-maven-plugin executions, profile activation, failsafe/surefire bindings) in this repository. The finished `ComposeFixtureImageBuildWiringTest` (`laneSelectorRequiresABuildBoundBeforeTheStart`) is the reference shape.
