# A threat-model coverage status is worded no stronger than its test evidence

A threat-model coverage status is a claim about tests, and it has to be worded no stronger than the evidence:

- red-before-fix counts are copied from the recorded red proof, not from the deliverable's intent;
- COVERED only when tests drive the production wiring end to end; a test that supplies its own dispatch function proves the unit, so the entry names the substituted steps and stays PARTIAL;
- distinguish "run by no test" from "asserted by no test", and check the integration suites (e.g. `GrpcProxyIT`) before claiming a path is not run;
- the status of one threat id is restated in the threat-model entry, the validation-matrix row and the ADR amendment: grep the threat id and change every restatement in the same commit.
