# TlsEdgeProducerTest flakes on macOS via wildcard ephemeral bind


## Context

`de.cuioss.sheriff.gateway.tls.TlsEdgeProducerTest.startsAndStopsFrontListener` failed
**three times** during PR #284's finalize (jobs `be5dc16d`, `d6b8abbe`, and one earlier),
each time on its own control precondition:

    control precondition: nothing owns the port before startup ==> expected: <false> but was: <true>

Each failure passed on an immediate re-run against the **identical tree**, and the same test
passed on every CI run (Linux) for the same commits.

## Why it happens

The fixture binds an ephemeral port to a wildcard host. On macOS a wildcard `listen(0)`
collides with foreign `127.0.0.1` listeners at a low but non-zero per-connect rate, so the
precondition observes a port that something else already holds. Two conditions raise the
rate sharply, and both occurred during this run:

- **Leftover containers.** A timed-out integration run left this plan's whole compose stack
  up, holding 20 published ports. Tearing it down cleared the first occurrence.
- **High load.** A load average of 70 (two VS Code windows, OrbStack, IntelliJ) widens the
  window in which the collision can happen.

## Directive

1. **Do not read this failure as a regression.** Establish provenance first: check whether
   the branch touches any TLS code, and whether the same test passed in CI on Linux for the
   same commit. Both answers were "no" and "yes" here.
2. **Check for orphaned containers before re-running** — `docker ps` and, when they belong
   to a plan's worktree, `docker compose --project-directory <worktree>/integration-tests down
   --remove-orphans`. A timed-out build does not clean up after itself.
3. **The durable fix is to bind the control listener explicitly**: `listen(0, "127.0.0.1")`
   rather than the wildcard. `LoopbackEphemeralBindArchTest` already exists to enforce
   exactly this and flags fixtures that pass a wildcard host literal — the production
   fixture predates it.

## Related

An arch test guarding this rule cannot see a `\uXXXX` escape in guarded source and reports
it as an offender. Write the literal character instead; the repository is UTF-8.
