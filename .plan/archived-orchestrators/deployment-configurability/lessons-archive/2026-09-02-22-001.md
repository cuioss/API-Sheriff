# A root-path label of "/" broke five ways on one branch - normalise it once at the boundary

## Observation

On one branch (`configurable-context-path`, PR #248) the **same defect class was found five
separate times**: a root-path label whose value is the single character `/` was mishandled at five
different places, in three different languages. Each was a real, independently-reported defect:

1. A shell `read` split a report row whose root-path column was empty for the `/` case, shifting
   every later column by one field.
2. A composed URL concatenated the root path with an endpoint path and produced `//metrics` for the
   `/` case.
3. A comparison tested the composed `//metrics` against the literal `/metrics` and reported a
   mismatch that did not exist.
4. and 5. Two further sites in the same family — a label rendered empty where a caller expected a
   printable token, and a path prefix stripped by length rather than by segment.

None of the five was a typing slip. `/` is the one root-path value where "prefix" and "separator"
are the same character, so *every* composition rule that is correct for `/gw` is wrong for `/`, and
the wrongness is one character wide and reads fine to a human.

## The signal

Five occurrences on one branch is not five mistakes. It is the observable consequence of there
being **no shared normalisation for the value**. The project composes and compares root paths in
shell scripts, in front-end JavaScript and in Java, and each site re-derived its own handling
inline. With no single place that answers "what is the canonical form of this label, and how do I
join it to a suffix", every new call site is a fresh chance to get the `/` case wrong, and no test
of one site protects any other.

## Directive

1. **When the same class of defect is reported three or more times on one branch, stop fixing
   instances.** The count is the finding. Write down what the instances share and fix that instead
   — here, the absence of a normalisation helper.
2. **Give a value with a degenerate case exactly one canonical form, and one join function per
   language boundary.** For a root path: normalise to no trailing slash (with the bare `/`
   normalising to the empty string), and join with a function that inserts exactly one separator.
   Composition then has no special case for `/` because the special case was consumed at
   normalisation.
3. **Test the degenerate value as a first-class case, not as an afterthought.** Every parameterized
   test over root paths must carry `/` as one of its parameters. Four of the five defects above
   would have been red on the first run of such a case.
4. **Where a shared helper genuinely cannot cross a language boundary, make the boundary format
   unambiguous instead.** The shell `read` failure was caused by an *empty column*, not by `/`;
   emitting a placeholder token (or switching the row format to one that survives empty fields)
   removes the whole family.

## Evidence

Five distinct review/test findings on PR #248 and its two closed wrappers (#246, #247), each traced
to a separate source location, each verified by turning the corresponding assertion red before the
fix and green after.
