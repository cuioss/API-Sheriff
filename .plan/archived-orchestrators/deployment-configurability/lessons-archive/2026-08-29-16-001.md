# A contract test guarding files outside the build-trigger set never runs on CI

A guard is only as good as the trigger that runs it. `BuildGateCoverageContractTest`
(`integration-tests/.../config/BuildGateCoverageContractTest.java`) asserts that a set of
globs is present in `.plan/marshal.json`'s `build.map`. Commit `cea163c` regenerated
`build.map` from its derivation and erased four of those globs (`Dockerfile*`,
`docker-compose*.yml`, `*.css`, `*.ts`). CI reported **green** for that commit.

## Why the green was empty

`cea163c`'s entire footprint was `.plan/marshal.json` + `CLAUDE.md`. Neither is a
build-triggering path, so the `build/build`, `sonar-build` and `deploy-snapshot` jobs were
all **skipped** — the contract test never executed. The guard was defeated by precisely the
coverage gap it exists to close: it asserts facts about a file class that cannot itself
trigger the job the assertion lives in.

## The generalizable shape

**A test that guards artifact X only protects X if a change to X triggers the job that runs
the test.** Whenever a guard's subject is a file the CI trigger set does not cover, the
guard is decorative — it passes forever, and the first regression it was written to catch
lands unseen.

## Corrective actions

1. When adding a contract/invariant test, name the file class it guards and check that class
   against the CI trigger paths. If the class is not build-triggering, the guard is not
   armed.
2. Fixes are one of: widen the CI trigger paths to include the guarded class; move the
   assertion into something that runs unconditionally (a path-independent job, a pre-push
   hook); or, when neither is available, document the gap explicitly at the guard so a later
   reader is not misled by its presence.
3. In this repository the workflows are **org-managed** (`cuioss-organization`), so option 1
   was not available to the branch that found this. PR #230 therefore documented the gap in
   `doc/development/build-gate-discipline.adoc` and restored the erased globs, rather than
   claiming to have closed it. Naming an open gap is a valid outcome; silently relying on a
   guard that cannot fire is not.

## Related

- The same run's `.plan/marshal.json` restore (PR #230) is the remediation of the *symptom*;
  this lesson is about the *mechanism* that let the symptom reach `main` unseen.
- `.github/workflows/*` is deliberately absent from `build.map`: that map answers "does this
  footprint need a Maven build?", and no Maven profile can observe workflow YAML. The
  gate-requiring list in `CLAUDE.md` is deliberately broader than `build.map`, and that
  divergence is why some footprints require the quality gate to be run **by hand**.
