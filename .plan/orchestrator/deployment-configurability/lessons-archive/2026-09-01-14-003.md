# Converting a wait onto a throwing helper silently kills the assertion that followed it

A wait-then-assert pair is a two-part construction: the wait gives the condition time to
become true, and the assertion is what fails the test if it never does. Converting the wait
onto a **throwing** primitive moves the enforcement into the wait — and silently makes the
trailing assertion dead code that can never fail.

## The shape

Before — the loop is permissive, the assertion enforces:

```java
for (int i = 0; i < 50 && !condition(); i++) {
    Thread.sleep(20);
}
assertTrue(condition());   // <-- this is what fails the test
```

After — `Awaits.until` throws on timeout, so control only reaches the next line when the
condition is already true:

```java
Awaits.until(() -> condition());
assertTrue(condition());   // <-- unreachable-as-a-failure; can never be false here
```

The assertion still compiles, still runs, still reads like a check, and is worth exactly
nothing. Worse, it *looks* like the test's guarantee, so a later reader who weakens or removes
the wait believes an assertion is still holding the line.

## What happened

This plan converted the edge-suite waits onto `Awaits.until`. At
`GatewayEdgeRouteTest:786` the conversion left the original trailing assertion of the same
condition in place. A review bot caught it; the local suite could not, because a dead
assertion produces no signal in either direction.

## Rule

After converting any wait or guard onto a throwing primitive, **re-check every assertion that
followed it**. The enforcing mechanism moved; the old enforcer is now either redundant or
misleading. For each trailing assertion, choose deliberately:

- **Asserts the same condition the wait now throws on** -> delete it. The wait is the
  assertion.
- **Asserts something narrower or different** (a value, not just presence; a second property)
  -> keep it, and make that distinction visible so it is not mistaken for the redundant case.

## Generalisation

This is one instance of a wider rule: **any refactor that relocates a failure mechanism owes a
re-check of everything that used to depend on the old location.** Converting to a throwing
helper, hoisting a check into a `@BeforeEach`, moving validation into a constructor, and
replacing a returned status with an exception all create the same class of newly-dead
assertion. A test that cannot fail is worse than an absent test, because it reports coverage
it does not provide.

## Evidence

Plan `stabilize-edge-suite-awaits` (2026-09-01, API-Sheriff), PR #241,
`GatewayEdgeRouteTest:786`; caught by an automated PR reviewer, not by the suite.
