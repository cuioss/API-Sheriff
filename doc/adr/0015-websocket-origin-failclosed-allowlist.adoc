== Status

Accepted

== Decision

=== The question

A `protocol: websocket` route proxies a browser-initiated upgrade. The browser's Same-Origin Policy does not restrain a cross-origin WebSocket connection: the browser opens a socket to any origin and attaches ambient credentials. The only defence against a malicious page opening an authenticated socket is a server-side `Origin` check on the handshake. An accept-any-origin upgrader is a cross-site WebSocket hijacking (CSWSH) hole, the class behind Nginx-UI CVE-2026-34403 and Dozzle CVE-2026-44985, and GW-09 in the link:../security-threat-model.adoc[threat model].

Three forces shape how the check is configured:

* *A bearer WebSocket route has no origin allowlist to reuse.* The field has to exist per route in any case.
* *CORS `allowed_origins` is a different trust decision.* It governs what the browser may do with an XHR or `fetch` response, and it is about response-header emission. The WebSocket `Origin` check is a per-route handshake admission made before the upstream is dialled.
* *Fail-open is the dangerous default.* An authenticated socket whose allowlist is absent or empty, if treated as "any origin", is the CSWSH hole, and nothing would reject it.

*The decision:* the per-route `websocket` block carries an `allowed_origins` field with fail-closed, exact-match semantics. link:../configuration.adoc#_allowed_origins[`configuration.adoc`] defines the field.

=== Exact match, no wildcards

Each entry is a full origin string (`scheme://host[:port]`). Matching compares scheme and port exactly and the host case-insensitively (RFC 6454, RFC 3986 section 3.2.2). There are no wildcards, suffix forms or regular expressions, and the boot refuses a wildcard entry.

=== Fail-closed, no "any origin" default

The handshake `Origin` must match a listed origin, or the gateway rejects the upgrade before any upstream dial.

[[amendment-a1]]
=== The boot check covers bearer and session routes

The boot refuses a `protocol: websocket` route whose effective auth is `require: bearer` or `require: session` and whose `websocket.allowed_origins` is absent or empty. The refusal names the route and its effective auth posture. A `session_fallback` route is a bearer-posture route (link:0055-A_session_fallback_route_carries_two_authentication_branches_selected_by_Authorization_header_presence.adoc[ADR-0055]) and is covered as one.

A session route's credential is a cookie the browser attaches to the upgrade on its own, and the handshake `Origin` tells the gateway which page opened the socket. A session route without an allowlist would have no origin check at all. The route declares the list explicitly, so one field and one boot rule cover both authenticated postures, and `session.csrf.trusted_origins` keeps its one meaning: the CSRF check on unsafe methods.

A `require: none` route may omit the list, unless its effective `cookies` block forwards a cookie (link:0037-The_gateway-owned_header_sets_are_enumerated_per_direction_and_bounded_by_knowledge.adoc[ADR-0037]). A declared allowlist is enforced at the handshake on every route, whatever its auth posture, and every entry is held to the exact-match rule.

The session cookie is `SameSite=Lax` in both session modes (link:0018-BFF_session_mode_is_one_SessionBinding_seam_behind_a_fixed_reserved-path_and_CSRF_model.adoc[ADR-0018]). The attribute and the allowlist are separate controls, and neither replaces the other.

== Alternatives rejected

=== Accept any origin by default

*Rejected outright.* It is the CSWSH hole itself.

=== Reuse `security_headers.cors.allowed_origins`

*Rejected because* it couples two unrelated trust decisions and would require inventing a route-level CORS override.

=== Wildcard or suffix matching

*Rejected because* it broadens the allowlist into the over-permissive matching that produces origin-confusion bugs.

=== Derive the allowlist from the route's `match.host`

*Rejected because* the calling page's origin and the gateway host are unrelated.

=== Reuse `session.csrf.trusted_origins` on a session route

A `require: session` WebSocket route could reuse that set, since the origin check and the CSRF posture look like one trust decision there. This was the first form of the decision for session routes.

*Rejected because* a bearer route needs the per-route field anyway, so reuse would give one check two sources. It would also give `session.csrf.trusted_origins` two meanings. An origin trusted for CSRF and meant to open a socket is written in both places instead.

== Consequences

=== Properties of the design

* CSWSH (GW-09) is closed for bearer and session WebSocket routes by construction: an unlisted origin cannot complete the handshake, and an empty allowlist is a loud boot refusal.
* The configuration surface grows one field with self-contained, boot-validated semantics. CORS and the WebSocket `Origin` check stay independent and separately auditable.
* The rejection comes before the upstream is contacted, so a hijack attempt never reaches it. It is observable as a handshake-time WARN (`ApiSheriff-105`).

=== Accepted costs

* A session WebSocket route carries its own list, so an origin trusted for both uses is written twice.
