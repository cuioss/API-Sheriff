== Status

Accepted for the `neededScopes` derivation, the bearer check and the `require: none` rule. The session half is superseded by
link:0057-Session_routes_obtain_their_declared_scopes_by_refreshing_inside_the_grant_and_widening_the_live_session_outside_it.adoc[ADR-0057].

== Decision

=== The question

A route carries OAuth scopes from two sources. The gateway-wide `oidc.scopes` are what every login asks the identity provider for. An endpoint can add more with `endpoint.scopes`, a list declared next to `auth`
rather than inside it. At boot `RouteTableBuilder` combines them into one set per route:

----
neededScopes(route) = oidc.scopes ∪ endpoint.scopes
----

The set is additive. An endpoint cannot remove a gateway-wide scope, and a route that overrides `auth` still needs its endpoint's scopes.

The set's meaning depends on the authentication posture:

* A *bearer* route receives a token minted elsewhere, often by a client the gateway never sees log in, `client_credentials` callers included. The gateway can only inspect the token.
* A *session* route holds a token the gateway obtained through a login it drove. The session outlives the route that started it.
* A *none* route has no token.

Scope handling can fail in three ways. It can *over-request*: every login asks for every scope any endpoint could need, so the token relayed everywhere is over-privileged. It can *under-check*: a route forwards a token
lacking a needed scope and relies on an upstream that may not check. Or requesting and checking can *drift*: they read different sets. This record settles how each posture uses the one set.

=== One set, used per posture

The gateway derives one scope set per route at boot. A bearer route enforces it, and a none route ignores it.

* *`require: bearer` enforces the full set.* `AuthenticationStage` compares the validated token's scopes against `neededScopes`. It rejects a token missing any member with `403` and the RFC 6750 challenge
  `WWW-Authenticate: Bearer error="insufficient_scope", scope="<missing>"`, before any upstream contact. The challenge lists only the missing scopes, sorted and taken from boot configuration, never from the token. The set
  includes `oidc.scopes`, so a bearer token lacking the gateway-wide scopes is rejected too, a `client_credentials` token among them. That tightening is deliberate: the gateway-wide scopes are a requirement of every authenticated
  route, not a default only the gateway's own logins observe. An empty set skips the check.
* *`require: none` does not use the set.* The boot refuses an endpoint that declares `endpoint.scopes` while every route resolves to `require: none`, because the declared scopes could never take effect.

The `auth` block has no scope list of its own. The schema refuses one, so endpoint scopes have one declaration and one derivation.

=== Where the check sits against the trust boundary

The scope check runs after the token validated, so its `403 insufficient_scope` challenge lies past the trust boundary of
link:0073-Untrusted_callers_get_the_unrouted_404_for_every_rejection_raised_before_the_trust_boundary.adoc[ADR-0073]. A missing or invalid token is raised before that boundary. On the shipped default the gateway answers it as an unrouted
address: `404`, no `WWW-Authenticate` challenge, and the true event (`TOKEN_MISSING` or `TOKEN_INVALID`) metered in `sheriff_errors_total`. With `security_defaults.uniform_not_found: false` the bearer route answers `401`.

=== The superseded session half

This record once let a session route use the set only to decide what its login requests, and it left a live session unchecked. ADR-0057 supersedes that half, because a live session can now be widened. A session route still requests its
`neededScopes` at login (ADR-0048). ADR-0057 states everything it does with a live session.

== Alternatives rejected

=== Check bearer tokens against `endpoint.scopes` only

Leave `oidc.scopes` out of the bearer check.

*Rejected because* tokens without the gateway-wide scopes would pass, `client_credentials` tokens included. The set a login requests and the set a bearer route checks would differ, which is the drift the single derivation prevents. A caller could bypass
the gateway-wide requirement by presenting a token minted elsewhere.

=== Pre-check live sessions and re-login for missing scopes

A session route compares the session's granted set against `neededScopes` and, on a shortfall, redirects to a new login for the wider set.

*Deferred here, not rejected.* It needs a way to widen a live session: a new login replaces the session, and RFC 6749 §6 forbids a refresh grant from widening the original scope. Without that the pre-check could only reject, with no recovery. ADR-0057 settles this with a
widening merge.

=== Narrow the token per endpoint

Relay each session route a token restricted to that route's scopes, through a scope-restricted refresh grant or RFC 8693 token exchange.

*Out of scope for this decision.* It would remove session-wide scope growth, but it adds a token-endpoint round trip per route or per-route token caching, and it needs identity-provider support that cannot be assumed. Session-wide growth stays the accepted residual.

All three move the check away from the single boot-derived set, or add a second mechanism next to it. The decision keeps one set and varies what each posture can do with it.

== Consequences

=== Properties of the design

* Bearer checks and login requests cannot drift apart. Both read the same boot-derived `neededScopes`. A token obtained through a login for a route passes that route's check by construction, and no route checks a scope no login would request.
* Under-checking is closed on bearer routes. A token missing a needed scope never reaches the upstream, and the rejection is a standards-conformant challenge a client can act on.
* Login requests are minimized. Only logins for an endpoint request its extra scopes.
* Scopes on an endpoint with only `none` routes get a boot refusal rather than silently doing nothing.

=== Accepted costs

* *`client_credentials` callers must request the gateway-wide scopes.* A machine client granted only its own scopes is rejected on every bearer route of a gateway that declares `oidc.scopes`. Operators register those scopes for such clients at the identity provider.

=== Risks

* *Session-wide scope growth is accepted.* The token relayed to every session route carries every scope the session holds. A session that logged in through a scoped endpoint presents that endpoint's scopes to every other session-route upstream. The identity provider granting only the requested
  scopes and `token_relay: false` on origins that need no token limit the exposure. The threat model tracks it as BFF-15.
