== Status

Accepted

== Decision

The gateway loads its routing and policy posture from YAML files at boot (`gateway.yaml`, `endpoints/*.yaml`). YAML lets a document define an anchor once and dereference it through aliases any number of times, and nest collections to any depth. A small "billion-laughs" alias graph or a deeply nested document expands to a memory- or CPU-exhausting structure during parse, so the process can go down before it serves a request. The record settles where in the load pipeline the guard has to live so that it is a real refusal.

*The decision:* the alias-expansion and nesting-depth caps are enforced in a dedicated SnakeYAML-native compose-only pre-pass that runs before the document is bound. This pre-pass is a permanent, load-bearing stage of the pipeline.

`ConfigLoader` realises it in two parts from the same limit constants (`MAX_YAML_ALIASES`, `MAX_YAML_NESTING_DEPTH`, `MAX_YAML_STRING_LENGTH`):

* *Compose-only pre-pass (`withinExpansionLimits`).* The loader composes the node graph through a bare `Yaml.composeAll(...)` under `LoaderOptions` carrying the caps, and advances the iterator so that the graph is walked. Advancing the `Composer` is what makes SnakeYAML count collection-alias dereferences against `setMaxAliasesForCollections` and depth against `setNestingDepthLimit`. A hostile document trips a cap and the composer throws. The pass constructs no Java objects from the nodes, so it opens no deserialization-gadget surface.
* *Hardened bind factory (`hardenedYamlFactory`).* The bind applies the same `LoaderOptions` and Jackson's `StreamReadConstraints` nesting-depth and string-length guards, so those limits hold on the bind path too.

The pre-pass exists as a separate stage because of a structural property of the Jackson and SnakeYAML integration: *Jackson's `YAMLParser` consumes SnakeYAML's event stream directly and never invokes the `Composer`.* The `Composer` is the only layer that counts collection aliases. A `mapper.readTree(...)` call therefore ignores `setMaxAliasesForCollections`, however the mapper's `LoaderOptions` are configured. Removing the pre-pass, or folding its caps into the bind mapper, silently disarms the billion-laughs defence.

Both passes consume one bounded in-memory snapshot of the file (`MAX_CONFIG_FILE_BYTES`), so the bytes the caps cleared are the bytes the bind parses. A tripped limit is a collected `ConfigError` and joins the aggregate boot refusal the rest of the loader uses.

== Alternatives rejected

=== Attach the caps to the bind mapper's `LoaderOptions` only

The minimal shape would configure the caps on the `YAMLFactory` and bind directly.

*Rejected because* it does not enforce the alias cap at all. The `Composer` never runs on that path, so the alias limit is silently inert while appearing configured. It gives a false sense of protection against the highest-impact expansion vector.

=== Post-parse structural inspection

The loader would bind first, then reject a bound tree that is too large or too deep.

*Rejected because* the expansion has already happened by the time a bound tree exists. The blow-up occurs during parse, so the check runs after the damage.

=== A hand-rolled YAML scanner

A custom scanner would bypass the engine's limit machinery.

*Rejected as* disproportionate and less safe. It reimplements security-sensitive parser internals the engine already provides, and it diverges from the engine's limit semantics.

An expansion-bomb guard must sit at the pipeline stage where the engine counts the expanding construct. For SnakeYAML's collection-alias cap that stage is the `Composer`, which the Jackson bind path bypasses.

== Consequences

=== Properties of the design

* The alias-bomb defence is armed, not merely configured. The nesting cap holds on both paths. `MAX_CONFIG_FILE_BYTES` (512 KiB) bounds every file before either pass, so it is what bounds a document and its longest string. `MAX_YAML_STRING_LENGTH` (1 MiB) sits above it: SnakeYAML applies that constant as a code-point budget over the whole stream on both paths, Jackson as its per-string limit on the bind path, and neither can trip on an accepted snapshot.
* The guard fires before any binding work, so a hostile document never reaches substitution, schema validation or model construction.
* The pre-pass opens no deserialization surface.
* A tripped limit joins the aggregate boot refusal, which keeps the "report all violations in one pass" contract.

=== Accepted costs

* Each document is parsed twice at boot. Configuration volume is small and one-shot, so the cost is immaterial.
* The two limit sites must stay in sync. Both read the shared `MAX_YAML_*` constants, and the duplication is intrinsic to the split.

=== Risks

* A refactor that deletes the pre-pass and trusts the bind mapper reopens the hole with no compiler signal, because the mapper accepts the options and ignores them. The method's Javadoc states this, and a negative test exercises an over-cap alias document. Both must survive any such refactor.
* The guard depends on SnakeYAML enforcing the alias cap only inside the `Composer`. An engine change that moved the count into the event stream would make the pre-pass redundant, not wrong.
