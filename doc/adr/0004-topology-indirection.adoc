== Status

Accepted

== Decision

Endpoint configuration should move between dev, staging and production without edits, while the concrete upstream locations differ per environment. The configuration model (link:../configuration.adoc[Configuration Model]) abstracts every upstream host behind an alias (`APP1`, `KEYCLOAK`, ...) that endpoint files reference, and binds each alias in `topology.properties`. The record settles the shape of a topology entry, how the environment overrides one, and how a route's path joins it.

*The decision:* a topology entry is a single URL per alias. An endpoint file never contains a concrete host, only the alias and an alias-relative path. Moving a deployment changes only the topology.

=== One URL, decomposed on read

`topology.properties` holds `APP1=https://app1.internal:8443/app1`. On load, `TopologyResolver` validates each resolved URL and decomposes it once into `{scheme, host, port, base-path}`. The rest of the gateway works with the structured components.

[[_amendment_a1]]
=== The override channel is an in-file placeholder

Every override point is a visible shell-style placeholder in the artifact it affects:

[source,properties]
----
APP1=${TOPOLOGY_APP1:-https://app1.internal:8443/app1}
----

`${VAR}` is a required substitution, and an unset variable is a boot refusal. `${VAR:-default}` keeps the file value as the default and lets the environment win. `TOPOLOGY_<ALIAS>` survives as a naming convention in the sample configuration. The mechanism is the placeholder, resolved once before schema validation. The operator guide's link:../user/environment-variable-overrides.adoc#_topology_and_endpoint_enablement[topology and endpoint enablement section] documents it.

[[_amendment_a2]]
=== `route.upstream.path` appends to the alias base path

A declared `route.upstream.path` is appended to the alias base path, joined on exactly one `/`. Aliases carry environments and routes carry paths.

----
effective base path = stripTrailingSlashes(alias base path) + "/" + stripLeadingSlashes(route.upstream.path)
                      -- both helpers remove REPEATED slashes at the seam, so exactly one "/" survives
forward URI         = stripTrailingSlash(effective base path) + <request-path remainder after the match key>
----

`RouteTableBuilder` strips all trailing slashes from the alias base path and all leading slashes from `route.upstream.path`, so an alias ending `/anything//` and an `upstream.path` of `//graphql` join to `/anything/graphql`. `RouteTableBuilderTest.shouldJoinOnExactlyOneSlash` covers that pair. A blank or absent `route.upstream.path` keeps the alias base path unchanged.

== Alternatives rejected

=== Split a topology entry into components

An entry could be split into scheme, host, port and path.

Machine-generated and service-discovery data planes (Envoy xDS, Kubernetes, APISIX admin API, HAProxy runtime) favour split components, which are easy to populate and diff programmatically. Human-authored declarative surfaces (Traefik `url`, Spring Cloud Gateway `uri`, Nginx `proxy_pass`, Kong's `url` shorthand) favour a single URL. The topology is a human-authored, environment-overridden surface.

*Rejected because* one variable beats four coordinated ones: the change is atomic and no override is half-applied. A single URL validates in one shot through `java.net.URI` and then yields the components anyway. Assembling a URL from parts is strictly more error-prone (default ports, IPv6 brackets, trailing slashes). The twelve-factor precedent treats a backing service's location as one atomic resource handle (`DATABASE_URL`, `REDIS_URL`). Kong stores components but accepts a write-only `url` decomposed on write, the model this record follows. The only real argument for splitting is partial override, which is rare and cheap to work around.

=== Per-component override keys

Keys such as `TOPOLOGY_APP1_PORT` would give a narrow escape hatch next to the full URL.

*Not implemented.* They may be added later only if a real partial-override need appears.

=== A convention-named environment override

`TOPOLOGY_<ALIAS>` could win over the file by convention.

*Rejected because* it is an invisible Java-class-level lookup that a reader cannot discover from the artifact. The placeholder expresses the same precedence in the file it affects.

=== `route.upstream.path` replaces the alias base path

*Rejected because* replace semantics made a route restate the environment-specific part of the location. With the integration alias `UPSTREAM=http://go-httpbin:8080/anything`, every benchmark-aspect route had to spell `upstream.path: /anything/<aspect>`. The `/anything` segment belongs to the environment the alias describes, yet the portable endpoint file repeated it, which is the coupling this record exists to remove.

The replace justification recorded in the code did not hold against the in-repo usages. The gRPC routes ride `GRPC_ECHO=http://grpc-echo:9000`, whose base path is empty, so append and replace produce the same URI for them. The benchmark-aspect routes were the only other users.

== Consequences

=== Properties of the design

* Relocating an upstream is a one-line change with no edit to portable endpoint files, also for a route that declares `route.upstream.path`.
* The design matches the dominant human-authored idiom, which minimizes surprise and parsing risk.
* Validation is single-shot and runs at boot. An unresolved alias or a malformed URL is a boot refusal (see link:0009-asymmetric-alias-resolution-failure.adoc[ADR-0009] for the additional-alias class).

=== Accepted costs

* A partial override, such as the port only, restates the whole URL.
* The benchmark overlay shifts the path of six integration routes. `docker-compose.benchmark.yml` repoints `TOPOLOGY_UPSTREAM=http://nginx-static:8080`, with no base path, so the `/proxy` route keeps its exact upstream URI as the proxied-static fairness baseline shared with the other gateways. One alias value cannot keep both route groups identical on that overlay: the six routes reach nginx-static at `/<x>` instead of `/anything/<x>`. nginx-static answers every path from one `location /` block with the same fixed `200 OK`, so the response bytes and the measured work are unchanged.
