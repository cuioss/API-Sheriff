== Status

Accepted

== Decision

=== The question

A route's one terminal action was to proxy to an `upstream`. Some deployments need the gateway to serve assets directly, without standing up and securing a separate static-file server. Two forces shape how:

* *Do not fork the outbound controls.* The gateway has a hardened upstream path (link:0008-data-plane-transport.adoc[ADR-0008]) with fixed-topology resolution, a scheme allowlist, an `EgressPolicy` and `followRedirects(NEVER)`. GW-05 in the link:../security-threat-model.adoc[threat model] closes only if every outbound fetch keeps those controls.
* *File paths are a traversal surface.* Encoded traversal, encoded slashes, mixed or double encoding, `%00`, overlong sequences, backslashes and `..;/` are spellings of one escape. A control that blocks one spelling but not the class is the Gravitee double-patch cautionary tale.

Two further routing needs do not fit a two-action model. Moving an address required an upstream that answers with a `3xx`, so the gateway proxied a request whose only purpose was to be sent elsewhere. And a route could be declared only as a `path_prefix`, so one address could not be claimed without claiming everything below it.

*The decision:* a route resolves exactly one terminal action: `upstream` (proxy), `asset` or `redirect`. The configuration validator enforces this on the resolved route.

=== Two asset sources

* `source: directory` serves from a local directory or volume mount, with the confined path resolved under the configured root and a bounded size. Classpath-embedded resources are out of scope.
* `source: upstream` serves from an upstream target through the shared topology model: the resolved `base_url`, the configured path and the confined remainder.

[[_shipped_surface_reconciliation]]
=== What the upstream source shares with the data plane

`UpstreamAssetSource` keeps the shared topology model and the GW-05 SSRF controls: a scheme allowlist, `followRedirects(NEVER)`, a bounded response byte cap and the gateway-owned envelope. It runs its bounded buffered fetch through a dedicated JDK `HttpClient` with a 5 s connect and 10 s read timeout. It does not use the streaming Vert.x client pool or the upstream guard, so the circuit breaker does not cover this leg.

=== Two rules govern both sources

* *Canonicalize and confine before the source is touched.* `cui-http`'s `URLPathValidationPipeline` canonicalizes the request path: percent-decoding, dot-segment and duplicate-slash collapse, and unconditional rejection of traversal, `%00`, overlong sequences and backslashes. `PathConfinement` then confines the normalized path to the configured root or prefix and rejects any escape. A generator-driven adversarial corpus proves the confinement against the class, not one spelling.
* *Authorization before source resolution.* The gateway enforces access before it resolves the source, so an unauthorized request never causes a directory read or an upstream fetch.

=== One gateway-owned response envelope

Both sources serve through `AssetResponseEnvelope`: a fixed content-type map (the gateway sets the type, never the source), `X-Content-Type-Options: nosniff`, `no-store` forced for `access: authenticated` regardless of source, a stripped `Set-Cookie`, and GET and HEAD only. For the upstream source this lets the gateway override a hostile `Content-Type`, strip an upstream `Set-Cookie` and force `no-store` on an authenticated asset that the upstream marked `Cache-Control: public`.

=== The forward policy does not reach an asset route

Asset routes carry no `forward` block, which under the three-mode model (link:0036-Forward_filtering_is_a_three-mode_policy_inside_an_authorised_route.adoc[ADR-0036]) would resolve forward-all. It does not matter. The edge computes the forward projection for every route, but the asset branch takes the terminal action without consuming it: the confined path and the request method alone resolve the source, and no client header or query parameter is carried into it. A `source: upstream` fetch is the gateway's own request. An asset route's exposure is bounded by authorization before source resolution, the confinement and the envelope, never by a forward list, so no asset descriptor needs a `forward` block to hold its posture.

[[_redirect_and_exact_routes]]
=== Redirect and exact routes

* *`redirect` is a terminal action.* The gateway answers a redirect route with the configured `status` (`301`, `302`, `303`, `307` or `308`) and `Location`, and never contacts an upstream. The status is mandatory, because browsers cache `301` and `308` and permanence should be an explicit operator choice. The `location` is written verbatim and reviewed for open-redirect spellings at boot. An external target requires the explicit `allow_external` opt-in. `keep_query` carries the raw inbound query string.
* *`match.path` declares an exact route.* A route's matcher declares exactly one of `path_prefix` or `path`. An exact `path` is compared as an un-normalized string against the canonical request path, so `/a` and `/a/` are distinct addresses.
* *Exact routes precede prefix routes.* The route table orders every exact route before every prefix route, and prefix routes keep the longest-prefix rule. Two exact routes on one `path` collide at boot unless host, method or a header matcher distinguishes them. An exact route never collides with a prefix route of the same string.
* *`base_url` is mandatory only with a proxy route.* A route that declares neither `asset` nor `redirect` is a proxy route, and an endpoint declares `base_url` exactly when it carries one. A declared alias must still resolve.

== Alternatives rejected

=== A parallel fetch stack of its own design for assets

An asset fetch that grew its own client and controls.

*Rejected because* it would duplicate, and inevitably drift from, the SSRF controls. GW-05 closes only if every outbound fetch keeps the same controls. The shipped JDK client is narrower than this alternative: it shares the topology model and carries the same scheme, redirect and size controls, and only the transport and the upstream guard differ.

=== Serve classpath-embedded resources

*Out of scope.* The gateway serves from a mounted directory or an upstream, so an asset is deployment material and not part of the artifact.

=== Standing up an upstream that answers `3xx` for a moved address

*Rejected because* the gateway would proxy a request whose only purpose is to be sent somewhere else, and an operator would run and secure a server for that alone.

== Consequences

=== Properties of the design

* A hostile or compromised upstream cannot dictate the gateway's response metadata.
* Canonicalize-then-confine plus the adversarial corpus closes path traversal for the whole asset surface (GW-11 in the threat model).
* Asset serving has a declared home through the `asset` anchor `type` (link:0013-anchor-type-access-axes.adoc[ADR-0013]), and an asset surface's audience is boot-enforced like any other anchor.
* An address move or a canonical-path redirect needs no upstream and consumes no forward projection. A redirect's exposure is bounded by authentication and the boot review of its `location`.
* The route-table builder and the configuration validator share one proxy-route predicate, so the conditional `base_url` rule cannot drift between them.
* A single address can be claimed without shadowing the paths below it, and an exact route can sit inside a prefix route's namespace to override one address.

=== Accepted costs

* The upstream asset source is a second outbound client to audit. A failing asset origin does not trip a circuit breaker, and its fetch is buffered and bounded rather than streamed.
