= ADR-0082: The BFF OIDC back-channel inherits the engine's host-address egress guard and relaxes it only for declared hosts

// summary: token-sheriff 0.9.9 applies an SSRF host-address guard to every discovery and back-channel call of its confidential client, refusing loopback, link-local, site-local and other internal addresses. == Status

Accepted

== Decision

=== The question

The BFF dials its identity provider for discovery, the pushed authorization request, the authorization-code exchange, refresh and refresh-token revocation. Until token-sheriff 0.9.8 the
engine dialled whatever address those calls resolved to. From 0.9.9 every such call passes a host-address guard (`EgressPolicy`) on the URL actually contacted, after the
`oidc.back_channel_origin` re-targeting (ADR-0069). The guard refuses a host that resolves to a loopback, link-local, site-local, unique-local, shared-address, any-local or
multicast address.

The guard is the right default for a URL an attacker can influence: a spoofed discovery document can advertise a token endpoint at `169.254.169.254`. It also refuses the most common
real deployment of a gateway, an identity provider on a private network. The gateway had no key for this leg, so adopting 0.9.9 as it stood would have broken every such login with
`SSRF egress blocked`, with no remedy in `gateway.yaml`.

=== One explicit list, nothing derived

The gateway adopts the guard unrelaxed (`technical_aspects.adoc`, "Adopting Upstream Security-Default Changes") and adds one key, `oidc.allowed_egress_hosts`. It is a list of bare host names or
IP literals that the engine exempts from the address refusal, host-exact, against the host actually dialled. The producer hands the list to the engine on every build, the empty list included.

* *Nothing is derived.* An omitted or empty list exempts no host. The host of `oidc.issuer` and of `oidc.back_channel_origin` are not exempted implicitly.
* *The list is the whole relaxation.* The engine's blanket `allowLoopbackEgress` is not exposed: it would relax every loopback address at once, where an entry names one host.
* *Boot refuses an entry that can never match.* A blank entry and an entry carrying a port are refused at `/oidc/allowed_egress_hosts`, by the review the JWKS list is held to (ADR-0011).

=== Why the JWKS rule is not copied

`token_validation.issuers[].jwks.allowed_egress_hosts` derives its single host from `jwks.url` when the list is omitted (ADR-0011). That derivation is safe there because the URL is an operator-declared
key endpoint of one issuer. The OIDC leg reaches endpoints the identity provider advertises in its discovery document. An allowance derived from `oidc.issuer` would be consulted for every
endpoint advertised on that origin, and a re-targeted call is judged on the back-channel host instead, so the derived value would not even name the host that is dialled. Declaring the host
makes the relaxation a reviewable, one-line operator decision with a name on it.

== Alternatives rejected

*Derive the allowance from `oidc.issuer` and `oidc.back_channel_origin`, as the JWKS list does.* The deployment would keep working without a new key. Rejected: it restores the permissive
behaviour the engine withdrew for the common case, silently, which is what the adoption policy rules out, and the issuer host is the browser-facing name, often not the host the gateway dials.

*Expose `allowLoopbackEgress`.* Rejected for the reason ADR-0011 gives for the JWKS leg: a host-exact entry covers the legitimate cases, and a boolean widens every loopback address.

*Adopt the default and document only.* Rejected: a private-network identity provider could then not be configured at all. The policy asks for an escalation of a default the gateway cannot
accommodate, and this is that escalation, answered with a key.

*Pin 0.9.8.* Rejected: the same release carries the engine-side DPoP issuance binding (ADR-0058) and the refresh classification for `invalid_scope`, and the pin would only postpone this decision.

== Consequences

* A deployment whose identity provider resolves to a private address must add the host to `oidc.allowed_egress_hosts` when it moves to this version. Without it, discovery, login and refresh
  fail with `SSRF egress blocked`; neither `oidc.egress_tls` key changes that, because TLS decides whether a certificate is trusted and the list decides whether an address may be dialled.
* The compose sample and every integration-test descriptor that dials `keycloak:8443` declares `allowed_egress_hosts: [keycloak]`, and a wiring test holds each descriptor to it.
* The unit-test fixtures that dial a loopback stub declare `127.0.0.1` in the same key, so the key is exercised by the production producer path. A matched control shows a loopback identity
  provider refused when the list names nothing.
* The DNS-rebinding window the engine documents stays: the guard resolves the host before the connection and the HTTP client resolves it again. The list does not narrow it.

== The rest of the 0.9.8 to 0.9.9 range

The repository's upstream-default policy asks for an explicit verdict on every change of the range, not only on the one this record is about. The whole delta was read; these are the
changes that touch the gateway.

[cols="3,4"]
|===
| Change in 0.9.9 | Verdict

| Host-address egress guard on the back-channel
| Adopted unrelaxed; relaxed per host by `oidc.allowed_egress_hosts` (this record).

| Engine-side DPoP issuance binding (`token_type` and `cnf.jkt`)
| Adopted; the gateway's own duplicate check and `ApiSheriff-134` are retired (ADR-0058). The nested DSL-JSON converters it reads the access token through are registered for native, and
  `TokenClientDslJsonReflectionTest` enumerates the client jar so the next one cannot be missed. Exactly three converters are new in the range, and all three are registered.

| Refresh refusal `invalid_scope` classified as `SCOPE_REFUSED`
| Adopted: backed off like a pre-redemption failure, the session and its refresh token are kept.

| An empty `aud` is present-but-mismatched (`isNotPresentForClaimValueType` removed)
| Adopted in the logout-token validator; the empty-audience case is refused as a mismatch.

| `TokenBuilder` takes a `SecurityEventCounter`
| Adopted by the signature-only verifier.

| Every JSON answer must declare `application/json`; front-channel endpoints must be `https`
| Adopted, no key. Documented as the operator contract in link:../configuration/tls-and-egress.adoc#_oidc_idp_response_contract[What the engine requires of the identity provider's answers]. The gateway's end-session guard
  was aligned to the engine's https-only rule, so a cleartext endpoint is reported as `ApiSheriff-135` instead of failing inside the engine.

| Startup initializer, JAX-RS mappers and further changes of the token-validation extension
| Inert on this gateway; verdicts in ADR-0074.

| JWKS loader failure handling, JWE size and decoding limits, the token lifecycle manager
| The gateway builds its own JWKS loaders and does not use the lifecycle manager; no gateway change.
|===
