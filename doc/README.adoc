= API Sheriff -- Documentation Index
:toc: left
:toclevels: 3
:toc-title: Table of Contents
:sectnums:
:source-highlighter: highlight.js

API Sheriff is a security-focused, lightweight API Gateway built on Quarkus and
Java virtual threads. It is a purpose-built gateway rather than a configuration
layer on top of an existing one -- the link:features-analysis.adoc[Feature Analysis]
shows that no existing OSS gateway covers the required combination of confidential-client
token mediation, correct forwarding-header normalization (RFC 7239 `Forwarded` +
`X-Forwarded-*` behind a trusted-proxy allowlist), RFC 9470 step-up, and datastore-free
distributed configuration (the last deferred past the initial release -- see the
link:features-analysis.adoc#_initial_scope[Initial Scope]).

This directory holds the design documentation; these documents define *what is built* and
*how the parts fit together*.

[IMPORTANT]
====
*0.2.4 is an ALPHA release.* The configuration surface and the APIs described here *may change
without a migration path* -- pre-1.0 rules apply, so breaking changes are made freely and no
deprecation shim or upgrade tooling is provided. Alpha is a statement about the *stability of the
surface*, not about code quality: the intended use is evaluation, integration and feedback. The
verified limitations at this cut are listed in link:../README.adoc#_known_limitations[Known
Limitations].
====

== Deployment Variants

The gateway ships as one binary that operates in one of three modes, selected by
configuration. Each has its own design section:

[cols="1,3"]
|===
| Variant | Description

| link:variants/01-base-gateway.adoc[1. Base Security Gateway]
| Stateless reverse proxy. Inbound `cui-http` security filtering + offline bearer-token
  validation on routes with `auth.require: bearer`. No browser session, no OIDC login flow.
  The shared foundation for the other two.

| link:variants/02-bff-session.adoc[2. BFF -- Session-based]
| Backend-For-Frontend acting as an OIDC confidential client. Tokens held *server-side*;
  the browser carries only an opaque session-id cookie. Stateful -- the `CLIENT-19` *stateful
  BFF* shape.

| link:variants/03-bff-cookie.adoc[3. BFF -- Cookie-based (non-session)]
| Backend-For-Frontend where the tokens travel only inside an AES-256-GCM encrypted
  `HttpOnly` cookie, decrypted per request. Stateless -- the `CLIENT-19` *stateless BFF* shape.

| Variant 2 -- three-layer guides
| Task-oriented companions to the Variant 2 design section above:
  link:user/bff-session.adoc[operator setup] (configure and run the server-session BFF) and
  link:development/bff-session.adoc[contributor guide] (build, test, and extend it).

| Variant 3 -- three-layer guides
| Task-oriented companions to the Variant 3 design section above:
  link:user/bff-cookie.adoc[operator setup] (configure and run the cookie-based BFF) and
  link:development/bff-cookie.adoc[contributor guide] (build, test, and extend it).
|===

== Architecture Decisions

[cols="1,5,2", options="header"]
|===
| ADR | Decision | Status

| link:adr/0001-java25-runtime-baseline.adoc[ADR-0001]
| Compile and run on Java 25 (LTS) for the full virtual-thread benefit; CI covers Java 25 and 26.
| Accepted

| link:adr/0003-forwarded-headers.adoc[ADR-0003]
| Accept both `Forwarded` and `X-Forwarded-*`, normalise them behind a trusted-proxy allowlist, emit `X-Forwarded-*` by default.
| Accepted

| link:adr/0004-topology-indirection.adoc[ADR-0004]
| Portable endpoint files reference `base_url` aliases resolved by `topology.properties`; an override is a visible `${TOPOLOGY_<ALIAS>:-default}` placeholder.
| Accepted

| link:adr/0005-module-structure.adoc[ADR-0005]
| One Quarkus module with a framework-agnostic seam kept by package layout and an arch gate.
| Superseded by link:adr/0062-Platform_mechanisms_are_preferred_over_hand-rolled_equivalents_and_the_framework-agnostic_core_rule_is_retired.adoc[ADR-0062]

| link:adr/0006-body-streaming-vs-httpresult.adoc[ADR-0006]
| Stream data-plane bodies with backpressure; `HttpResult<T>` materialisation on the control plane only; `max_body_bytes` is a streaming counter.
| Accepted

| link:adr/0007-anchor-scoped-policy.adoc[ADR-0007]
| Anchors: disjoint path namespaces in `gateway.yaml` carrying an inherited, non-weakenable policy floor, erased into the route table at boot.
| Accepted

| link:adr/0008-data-plane-transport.adoc[ADR-0008]
| Data plane on the Vert.x `HttpClient` shared per upstream tuple; per-route SmallRye Fault Tolerance; no gateway-side response cache; `cui-http` client is control-plane only.
| Accepted

| link:adr/0009-asymmetric-alias-resolution-failure.adoc[ADR-0009]
| An unresolvable enabled-endpoint alias aborts boot; an unresolvable `passthrough_sni` alias is skipped; the validator is the single reporter.
| Accepted

| link:adr/0010-YAML_expansion_limits_enforced_in_a_compose-only_pre-pass_before_bind.adoc[ADR-0010]
| YAML alias-expansion and nesting caps run in a compose-only SnakeYAML pre-pass before Jackson binds.
| Accepted

| link:adr/0011-gatewayyaml_exposes_JWKS_trust_and_egress_as_neutral_names_bound_by_the_deployment.adoc[ADR-0011]
| The JWKS issuer surface exposes egress and trust as neutral names; one mapping component binds trust profiles to runtime anchors.
| Accepted

| link:adr/0013-anchor-type-access-axes.adoc[ADR-0013]
| Every anchor carries two orthogonal axes, `type` (`proxy`/`bff`/`asset`) and `access` (`public`/`authenticated`), validated fail-closed.
| Accepted

| link:adr/0014-asset-serving-terminal-action.adoc[ADR-0014]
| Asset serving is a second terminal action (`directory` or `upstream` source) with a gateway-owned envelope and canonicalise-and-confine path safety.
| Accepted

| link:adr/0015-websocket-origin-failclosed-allowlist.adoc[ADR-0015]
| WebSocket `Origin` is checked against a fail-closed exact-match allowlist before any upstream dial.
| Accepted

| link:adr/0016-grpc-trailers-only-rejection-mapping.adoc[ADR-0016]
| gRPC rejections are trailers-only responses with a canonical status mapping; pre-trust rejections are the `404` of ADR-0073.
| Accepted

| link:adr/0017-Accept-time_SNI_split_at_a_dedicated_front_listener_passthrough_relays_opaquely_at_L4_everything_else_terminates_internally.adoc[ADR-0017]
| A raw-TCP front listener splits on SNI at accept time: passthrough relays opaquely at L4, everything else terminates internally.
| Accepted

| link:adr/0018-BFF_session_mode_is_one_SessionBinding_seam_behind_a_fixed_reserved-path_and_CSRF_model.adoc[ADR-0018]
| Session mode selects only the `SessionBinding`; reserved paths, CSRF and session identity are fixed, mode-neutral models.
| Accepted

| link:adr/0019-Reserved_BFF_paths_bypass_the_url-parameter_value_pipeline_and_the_cookie-header_length_relaxation_is_gateway-wide.adoc[ADR-0019]
| Reserved BFF paths bypass the url-parameter value pipeline; the cookie-header length relaxation is gateway-wide.
| Accepted

| link:adr/0036-Forward_filtering_is_a_three-mode_policy_inside_an_authorised_route.adoc[ADR-0036]
| Forward filtering is a per-dimension three-mode policy (positive-list, negative-list, forward-all) inside an authorised route.
| Accepted

| link:adr/0037-The_gateway-owned_header_sets_are_enumerated_per_direction_and_bounded_by_knowledge.adoc[ADR-0037]
| The gateway owns four per-direction header sets (never-forward, response strip, identity, protocol), each enumerated in full.
| Accepted

| link:adr/0039-The_distroless_images_health_check_is_answered_by_the_application_binary_before_boot.adoc[ADR-0039]
| The distroless image's `HEALTHCHECK` is answered by the application binary before boot with a protocol-blind TCP probe.
| Accepted

| link:adr/0062-Platform_mechanisms_are_preferred_over_hand-rolled_equivalents_and_the_framework-agnostic_core_rule_is_retired.adoc[ADR-0062]
| Platform mechanisms are preferred over hand-rolled equivalents; the framework-agnostic core rule is retired.
| Accepted

| link:adr/0073-Untrusted_callers_get_the_unrouted_404_for_every_rejection_raised_before_the_trust_boundary.adoc[ADR-0073]
| Every rejection raised before the trust boundary answers as the unrouted `404`, behind a timing floor.
| Accepted

| link:adr/0074-The_token-validation_extensions_metrics_collector_observes_the_gateway_validator_and_its_health_probes_stay_excluded.adoc[ADR-0074]
| The token-validation metrics collector is kept; its two health probes stay excluded.
| Accepted; supersedes link:adr/0027-The_token-validation_extensions_unqualified_beans_are_excluded_not_accommodated.adoc[ADR-0027]
|===
