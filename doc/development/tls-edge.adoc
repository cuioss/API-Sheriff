= API Sheriff -- TLS Edge: Front Listener and the Accept-Time SNI Split

:toclevels: 3
:toc-title: Table of Contents

:source-highlighter: highlight.js

The *contributor* view of the TLS edge: how the accept-time SNI split is built, which component
owns which port, and why selection is *fail-closed*. Operators configuring these keys want the
link:../user/tls-edge.adoc[operator TLS-edge topic]; the field contract is the
link:../configuration/tls-and-egress.adoc#_tls[Configuration Reference `tls` section]; the threat this design
closes is link:../security-threat-model.adoc#gw-06[GW-06] in the threat model.

The whole edge lives under `de.cuioss.sheriff.gateway.tls` plus one pipeline stage
(`de.cuioss.sheriff.gateway.pipeline.PassthroughHostGuardStage`). The package is bound to the
platform: it uses Vert.x, the Quarkus TLS registry and CDI types directly. Its review against
link:../adr/0062-Platform_mechanisms_are_preferred_over_hand-rolled_equivalents_and_the_framework-agnostic_core_rule_is_retired.adoc[ADR-0062]
changed no class. A class of the package is an `@ApplicationScoped` bean where the container has to
find it or call it; the annotations on the classes are the record of which ones those are, and the
package documentation (`tls/package-info.java`) states the rule. `ClientHelloSniParser` is the one
hand-written component and stays: no platform API yields the SNI of a connection that must not be
terminated.

== Front Listener (Vert.x `NetServer`)

The leftmost component is `SniFrontListener` -- a *plain-TCP* Vert.x `NetServer` that binds the
public TLS port. It is plain TCP on purpose: the TLS ClientHello is sent in cleartext at the record
layer, so the Server Name Indication (RFC 6066) can be read *without any decryption or private key*.
The front never holds the gateway's certificate; it only reads the SNI and forwards bytes.

On each accepted connection an `Incoming` reassembles the ClientHello:

* the connection owns its own *incremental* `ClientHelloSniParser` and offers it every chunk it
  receives exactly once (`offer(...)`). The parser consumes only the TLS records the new bytes
  complete and never re-parses what it has already consumed, so a ClientHello dripped one byte at a
  time, or split across many tiny records, costs work linear in its length. The chunks are also kept
  in a per-connection buffer, solely so the relay can replay the ClientHello byte-identically;

* the parser answers `Result.needMoreData()` until the full ClientHello is present -- across as
  many records as it spans -- and only then a complete verdict, so the listener *never routes on a
  partial ClientHello* (a fragmented-ClientHello defence, see <<_fail_closed_gw_06>>). Reassembly is
  bounded by `ClientHelloSniParser.MAX_CLIENT_HELLO_BYTES` (32 KiB): a ClientHello that has not
  completed within the bound is a complete verdict with no SNI, which fails closed;

* once the parser reports a complete ClientHello the socket is *paused* (`socket.pause()`), the
  per-connection `settled` latch is set, and the connection is routed exactly once.

The data, exception and close handlers and the deadline timer of a connection all run on that
connection's Vert.x event loop, so the reassembly buffer, the parser and the `settled` latch are
single-threaded and need no synchronization. Three states are shared across the front's event loops:

* *The counter of the undecided-connection cap* is claimed with an atomic increment and rolled back
  with an atomic decrement when the claim overshoots the cap.
* *The per-source counts of the share* are claimed and returned inside `ConcurrentHashMap.compute` on
  the source key, which is atomic per key. A source is removed when its count reaches zero, so the map
  never holds more entries than there are held slots. A share refusal rolls back the global slot the
  connection had already claimed, so a refused connection holds neither.
* *The time of the last refusal `WARN` per reason* is advanced with a compare-and-set, so of two
  concurrent refusals at most one logs at `WARN`.

An admitted connection returns its two slots together, exactly once. Whichever comes first of the
route decision, the connection closing or failing, and the deadline sets the `settled` latch. A close,
a failure or the deadline returns the slots at once. The route decision does not: the connection keeps
its slots until the relay's backend dial settles (see <<relay-dial-bound>>), and the listener returns
them in the single completion handler of the dial-phase future `PassthroughRelay.relay(...)` returns.

The front listener is *conditional*: `TlsEdgeProducer` constructs and starts it only when
`tls.passthrough_sni` is non-empty. When passthrough is unconfigured the front is never created, the
terminated Quarkus HTTPS listener owns the public port directly, and the edge adds *zero* runtime
overhead -- the default single-listener topology is unchanged.

[#front-listener-bounds]
=== The bounds of the front

Four bounds keep a connection the front has not routed yet, or a relay nobody uses, from being held
indefinitely, or one source from holding the others off. None of them is configurable.

* *ClientHello deadline* -- `SniFrontListener.CLIENT_HELLO_DEADLINE`, 10 s. The timer is armed when the
  connection is accepted and cancelled when the connection settles; a connection that has not
  completed its ClientHello by then is closed, without an answer. A legitimate client sends its
  ClientHello in its first flight, so the deadline only ends a silent, stalled or dripping
  connection. The close is logged at `DEBUG` with the disposition only, never the bytes received.

* *Undecided-connection cap* -- `SniFrontListener.MAX_UNDECIDED_CONNECTIONS`, 1024 connections
  accepted and not yet routed, or routed and still waiting for the relay's backend dial to settle,
  across every event loop of the front. A connection accepted beyond the
  cap is closed at once, without reading from it. An undecided connection has received less than
  `ClientHelloSniParser.MAX_CLIENT_HELLO_BYTES` (32 KiB) -- the parser reaches its verdict as soon as
  that much has arrived -- and between two reads holds those bytes in three copies: the listener's
  replay buffer and the parser's received and reassembled arrays. Between reads, the cap therefore
  bounds the front's pre-route buffer memory at 1024 x 3 x 32 KiB = 96 MiB. The trade-off is
  deliberate: a client that holds 1024 silent sockets makes new handshakes wait for at most one
  deadline window per wave of such sockets -- the deadline frees every slot again -- and that bounded
  delay is preferred over unbounded pre-route memory.
+
*What the 96 MiB does not include.* Two amounts lie outside it. Each is stated for the transport's
default read sizing: Netty's adaptive receive allocator, whose largest single read is 64 KiB. The
front sets no receive-buffer option.
+
.. *The deciding read, whole.* The read that decides a connection is appended to the replay buffer in
   full, because the relay replays the client's bytes exactly. That buffer therefore ends up to one
   read past 32 KiB, which keeps it below 96 KiB. The parser truncates only its own copy.
.. *Transient copies.* While a read is processed, its bytes exist twice more: as the transport's buffer
   and as the copy offered to the parser. The extension walk of a complete ClientHello copies it once
   more. That is at most 64 + 64 + 32 KiB per event loop, since an event loop processes one read at a
   time.
+
*The dialing window is inside the cap.* A decided connection keeps its slot while the relay dials its
backend, so a dialing connection counts against the cap and its source's share like an undecided one.
At the route decision the listener drops the parser and its own reference to the replay buffer, so a
dialing connection holds only the replay buffer, below 96 KiB, and the relay drops that too as soon as
the client is known gone. The window is bounded by `TlsEdgeProducer.RELAY_CONNECT_TIMEOUT`, 10 s -- see
<<relay-dial-bound>>.

* *Per-source share* -- `SniFrontListener.MAX_UNDECIDED_PER_SOURCE`, a fixed quarter of the cap (256
  connections), held by one source at the same time. A connection accepted while its source already
  holds its full share is closed at once, without reading from it, exactly like one beyond the cap. One
  source filling its share therefore leaves three quarters of the cap to every other source, instead of
  starving them all. The quarter mirrors the quarter derivation of
  link:../adr/0020-WebSocket_relays_hold_their_admission_permit_for_the_connection_lifetime_and_are_bounded_by_a_derived_sub-budget.adoc[ADR-0020].
  See <<front-refusal-keying>> for what a source is.

* *Relay idle timeout* -- the Vert.x idle timeout of the front's `NetServer`, which `TlsEdgeProducer`
  also sets on the relay's dial `NetClient`, so both legs of every relayed connection -- passthrough
  and terminated alike -- carry it. A leg that carries no byte in either direction for that long is
  closed by Vert.x, and `PassthroughRelay`'s close handlers propagate the close to the other leg; the
  relay itself sets no timer. `TlsEdgeProducer.relayIdleTimeout(...)` derives the value once at boot
  as `max(quarkus.http.idle-timeout, gRPC stream-idle bound, longest effective WebSocket
  idle_timeout_seconds) + 60 s`. The gRPC bound is `GrpcStreamIdleBound.STREAM_IDLE_TIMEOUT_MILLIS`
  (five minutes), and the route table materializes the WebSocket value on every WebSocket route, the
  300 s default included. A derivation is required rather than a fixed value because
  `idle_timeout_seconds` has no upper bound: only a value computed from the route table guarantees
  that the relay never closes a connection before an idle bound inside the gateway would. The 60 s
  margin lets the inner close -- a WebSocket close frame, gRPC trailers, the HTTP idle close -- cross
  the relay first. No configuration key reaches the value; it moves only with the values it is derived
  from.

The threat these bounds answer is recorded under
link:../security-threat-model.adoc#gw-07-sni-front[GW-07 -- the SNI front listener].

[#relay-dial-bound]
=== The relay's backend dial

*The dial is bounded.* `TlsEdgeProducer.relayClientOptions(...)` sets the fixed
`TlsEdgeProducer.RELAY_CONNECT_TIMEOUT`, 10 s, as the connect timeout of the relay's dial `NetClient`,
replacing the implicit Vert.x default of 60 s. A dial that has not connected by then fails, and the relay
closes the accepted client connection. The value is not configurable; a package-private overload that
takes the connect timeout exists only so a test can shorten it.

*The slot is held until the dial settles.* `PassthroughRelay.relay(...)` returns a `Future<Void>` that
completes once the dial phase is over. Three paths end that phase and race each other: the relay is
established, the dial fails or times out, or the client closes during the dial. Each completes the same
promise with `tryComplete`, so the future completes exactly once, with the first of them. All three run on
the event loop of the accepted connection. `SniFrontListener` returns the connection's two slots -- of
the cap and of its source's share, as one unit -- in that future's single completion handler. The
ClientHello deadline is still cancelled at the route decision; from then on the connect timeout bounds
the connection instead.

*The ClientHello is released early.* At the route decision the listener's `Incoming` drops its parser
and its reference to the replay buffer, so the parser's two copies of the ClientHello are released at
once and the relay is the buffer's only owner. The relay keeps the buffer in a single-owner holder: the
dial success takes it to replay it, and the client-gone close handler clears it, so a client that leaves
during the dial frees the bytes at once rather than when the dial later completes. A dial that succeeds
after the client left still gets no session -- its backend leg is closed at once.

[#front-refusal-keying]
=== Refusals at accept: the source key, the WARN and the counter

*The source is the TCP peer address.* `SniFrontListener` keys the share on the accepted socket's
`remoteAddress().hostAddress()`; every connection whose peer address is unavailable shares one fallback
source. The edge's `SourceKeys` (`edge/admission`) is deliberately *not* reused, for two reasons:

* it resolves a source from an `HttpServerRequest` -- the address a trusted forwarder reported and the
  `Host` header -- and neither exists before the ClientHello at L4;
* importing it from `tls` would close a package cycle: `edge.admission.SourceKeys` ->
  `edge.request.EdgeRequests` -> `tls.RelayedPeerRegistry`. The `EdgeSubPackageArchTest` guard
  (ADR-0068) judges only the sub-packages of `edge`, so nothing would fail; the cycle is avoided by
  design, not by a test.

Behind an L4 load balancer that does not propagate client addresses, every client shares one source,
and the share then acts as a global sub-cap of 256 concurrent undecided connections. That still admits
tens of thousands of one-round-trip handshakes per second, and is an accepted trade-off. Like every
front bound, the share is not configurable.

*Every refusal is visible.* A connection closed at accept -- beyond the cap or beyond its source's
share -- is:

* *counted* on `sheriff_front_connections_refused_total{reason}`, with `reason` `cap` or
  `source_share`. The listener stays free of Micrometer: it reports each refusal to a plain
  `Consumer<SniFrontListener.Refusal>` callback, which `TlsEdgeProducer` wires to the two record methods
  of `SheriffMetrics`. Each of those fixes its own label value, so the label set is closed by
  construction, and the metrics adapter needs no type from `tls`.
* *logged* as `WARN ApiSheriff-146` (`ApiSheriffLogMessages.WARN.FRONT_CONNECTION_REFUSED`), at most once
  per `SniFrontListener.SATURATION_WARN_INTERVAL` (60 s, measured on the monotonic `System.nanoTime()`
  clock) per reason, with the reason token (`cap` / `source-share`), the bound that was full and the
  window. Every further refusal of that reason inside the window is logged at `DEBUG`. Neither line
  ever names the peer address or a received byte.

The package-private constructor of `SniFrontListener` takes the share, the warn window, the clock, the
source key and the recorder explicitly. A test drives a second warn window by advancing its own clock
instead of waiting a minute, and assigns connections to sources through the source key, because a
second loopback address is not available on every platform; the production key itself,
`SniFrontListener.sourceOf`, is pinned by a case in which two connections from one address share one
share.

== The Accept-Time L4/L7 Split

`SniFrontListener.route(...)` makes a single decision per connection, keyed on the normalized SNI:

* *SNI present in the passthrough map* -> the connection, *buffered ClientHello included*, is handed
  to `PassthroughRelay` as an *opaque L4 TCP relay* (`RelayKind.PASSTHROUGH`). The intact,
  still-encrypted byte stream is spliced to the resolved backend; the backend completes the
  handshake and presents *its own* certificate. The gateway never terminates and sees no L7 detail.

* *any other SNI* -> the same still-encrypted stream is relayed (`RelayKind.TERMINATED`) to the
  *internal* terminated Quarkus HTTPS listener, which completes the handshake with the gateway's own
  certificate -- enforcing `min_version`, `alpn`, and `mtls` client-certificate verification -- and
  runs the full fixed L7 pipeline.

* *missing / malformed SNI* -> the terminated-strict path, plus an audited `WARN`
  (`CLIENT_HELLO_FAIL_CLOSED`) that records the disposition only, never raw bytes. This is the
  fail-closed branch (<<_fail_closed_gw_06>>).

SNI matching is *exact, case-insensitive, and root-dot-insensitive*. `normalizeSni(...)` lowers the
host in the root locale, strips it, and removes a single trailing FQDN dot; `TlsEdgeProducer` builds
the relay-map keys through the same routine so insertion and lookup always agree. There is *no
wildcard* matching -- every passthrough host is listed literally.

== Internal-Handoff Mechanics and Port Ownership

There are two ports, wired by `TlsEdgeProducer`:

[cols="1,2,3"]
|===
| Port | Config property (default) | Owner

| Public TLS port
| `sheriff.tls.public-port` (`8443`)
| The `SniFrontListener` `NetServer` when passthrough is active; otherwise the terminated Quarkus
  HTTPS listener directly.

| Internal HTTPS port
| `sheriff.tls.internal-https-port` (`8444`)
| The terminated Quarkus HTTPS listener, bound to `localhost` only. Every non-passthrough connection
  is relayed here for termination.
|===

The internal handoff is a *loopback relay*, not an in-process call: terminated connections are
spliced from the front listener to `localhost:8444`, where the ordinary Quarkus HTTPS listener does
the TLS termination and L7 processing it would do anyway. This keeps the terminated pipeline
identical whether or not the front listener is present -- the split is purely an accept-time
prefix, and the terminated listener is unaware it sits behind a relay.

The one thing the relay hands over is the client's address, and it does so in process, never in a
header. Every terminated connection reaches the internal listener from the relay's loopback leg, so
the edge would otherwise see one peer for every client. A terminated relay registers its backend
leg's local socket address (host and port) against the client's address in the
`RelayedPeerRegistry` after the dial succeeds and before it writes the buffered ClientHello, and
releases the entry when the session closes on either leg. The edge records the client's address on
the request only on an exact hit for the request connection's remote address, so a connection the
relay did not dial gets nothing, whatever it sends. Once the internal HTTPS port is recorded (see
below), a hit is honoured only when the request arrived on that port or on a local address the
transport did not supply; a hit on a connection whose known local port is another listener's names no
client and is not marked either, since the relay dials no other listener. The address feeds only the
pending-login quota key (`PendingQuotaKeys`); the TCP peer every other stage reads stays the relay
leg.

The quota key fails closed without that hit. When `tls.passthrough_sni` is set, `TlsEdgeProducer`
records the internal HTTPS port in the registry, and a request without an exact hit -- a connection
the relay never dialled, or one whose relay session has already ended -- is marked unattributed
(`PipelineRequest.unattributedTerminatedLeg()`) when it arrived on that port. A request whose local
address the transport did not supply is marked unattributed too: without it the registry cannot
show that the request arrived on another listener, so it fails closed. `PendingQuotaKeys` keys such
a request on its own TCP peer and never reads its `X-Forwarded-For` or `Forwarded` header for it,
even when that peer is listed in `forwarded.trusted_proxies`. A registry hit honoured under the rule
above keeps the relayed client's address, and without a front listener every hit is honoured and no
request is marked, so the forwarded-header rules apply exactly as configured.

`TlsEdgeProducer` builds the immutable SNI -> `RelayTarget` map from `GatewayConfig.tls()` and the
resolved topology. Per link:../adr/0009-asymmetric-alias-resolution-failure.adoc[ADR-0009] an
unresolved passthrough alias means the `ConfigValidator` already failed the boot, so a present entry
that unexpectedly fails to resolve is skipped defensively rather than aborting a second time. Boot is
*fail-fast*: the front listener's port bind is awaited (15 s timeout) and a bind failure aborts
startup, so the gateway never serves on a half-open TLS edge.

== Runtime Host-vs-SNI Smuggle Guard

The L4 split routes on the *outer SNI*, but a terminated request also carries an L7 `Host` header,
and the two can disagree. `PassthroughHostGuardStage` is the runtime half of the guard: a *pre-check
before stage-2 route selection* that rejects a terminated request whose `Host` names a
`passthrough_sni` hostname with `404` (`EventType.PASSTHROUGH_HOST_SMUGGLED`).

A passthrough hostname is meant to be split off at L4 and never terminated. A terminated request
carrying that hostname in its `Host` header is therefore attempting to reach the passthrough
backend's reserved identity *through* the terminated listener -- a host-confusion / request-smuggling
vector. The guard's `Host` normalization mirrors the front listener's SNI normalization (lower-cased,
trailing FQDN dot removed) and additionally strips a single `:port` suffix, so the two matchers agree
on what "the same host" means.

This runtime guard is distinct from its two boot-time and framing siblings:

* the *boot-time collision rule* (`EdgeRules.validatePassthroughHostCollision`) fails startup
  when a route's `match.host` equals a passthrough SNI; and

* the framing / anti-smuggling `FramingGate`, which is orthogonal request-framing hygiene.

The stage is inert when `passthrough_sni` is empty and consumes only the `PipelineRequest`. It needs
no platform type, and nothing requires it to stay that way: `pipeline` is no longer a
framework-free package
(link:../adr/0062-Platform_mechanisms_are_preferred_over_hand-rolled_equivalents_and_the_framework-agnostic_core_rule_is_retired.adoc#narrowed-pre-boot-rule[ADR-0062,
the narrowed pre-boot rule]).

[#_fail_closed_gw_06]
== Fail-Closed Selection (GW-06)

Selection is *fail-closed*: anything not *positively matched* as a passthrough SNI is terminated
under the strict policy, never relayed and never dropped to a permissive default. Two rules make
this concrete, and both are direct responses to real gateway CVEs catalogued under
link:../security-threat-model.adoc#gw-06[GW-06]:

* *Full-ClientHello reassembly before routing.* The listener offers every chunk to the connection's
  `ClientHelloSniParser` until it reports a complete ClientHello, however many records it spans, and
  only then decides. This defeats the *fragmented-ClientHello* class:
  *Traefik CVE-2026-32305*, where a fragmented ClientHello yielded an empty SNI that fell through to
  a *permissive* default TLS config and bypassed mTLS. A partial ClientHello here yields no decision
  at all -- the front waits for the rest, for at most the ClientHello deadline
  (<<front-listener-bounds>>), and then closes the connection rather than route it.

* *Empty/unresolved SNI takes the strict path, never a permissive default.* A missing or malformed
  SNI is routed to the terminated-strict listener (which still enforces `mtls`), not to a
  passthrough or a no-client-cert fallback. This is the corrective for the *silent verify-inversion*
  class -- *Traefik CVE-2025-66491*, where `proxy-ssl-verify: on` was mapped to Go's
  `InsecureSkipVerify: true`, leaving verification *off* for months. The edge never expresses "verify
  off" as a fallback; the strict listener is the only non-passthrough destination.

Host-name normalization for the security decision is spec-conformant and tested, closing the
*normalization-bypass* class -- *KrakenD CVE-2026-39821*, where a punycode host (`xn--example-.com`)
normalized to `example.com` and bypassed a host-based rule. The passthrough collision rule and the
runtime `Host` guard share the same normalization routine, so a punycode host that normalizes onto a
passthrough SNI is caught by the same match rather than slipping between two disagreeing normalizers.

The discipline the CVEs teach is *assert behaviour, not the flag*: the integration suites verify a
real no-cert handshake *fails* when mTLS is enabled and a fragmented/empty-SNI ClientHello never
reaches a passthrough or a no-client-cert default -- not merely that a boolean parsed.

[[_server_tls_policy_binding]]
== Server-TLS Policy Binding (Two Seams)

`gateway.yaml` is the single effective source of server-TLS *policy*
(link:../adr/0025-The_whole_server-TLS_surface_is_neutral_in_gatewayyaml_and_bound_by_exactly_two_seams.adoc[ADR-0025]).
Because the terminated HTTPS listener and the management listener share no Quarkus hook, two
seams bind the policy:

[cols="1,2,2", options="header"]
|===
| Listener | Seam | Why it is the only one available

| Terminated main HTTPS listener
| `TlsServerCustomizer`, an `HttpServerOptionsCustomizer` mapping `tls.min_version`,
  `tls.cipher_suites` and `tls.alpn` onto the protocol set, cipher allowlist and ALPN protocols.
  `MtlsServerCustomizer` is its sibling for `tls.mtls`.
| Quarkus runs customizer beans in `doServerStart` *after* `createSslOptions`, so the customizer is
  the last writer. `quarkus.tls.*` does not work here: that registry applies only when the
  certificate also comes from it, and this gateway supplies it through
  `quarkus.http.ssl.certificate.*`.

| Management interface
| `NeutralTlsConfigSource`, a SmallRye `ConfigSource` projecting `management.tls.enabled: false`
  onto `quarkus.management.tls-configuration-name`.
| `VertxHttpRecorder.initializeManagementInterface` never enumerates `HttpServerOptionsCustomizer`
  beans, so a config source is the seam *by elimination*.
|===

*The projecting source runs before CDI exists.* `NeutralTlsConfigSource` re-reads `gateway.yaml`
with SnakeYAML under the same expansion-bomb caps as the authoritative loader
(link:../adr/0010-YAML_expansion_limits_enforced_in_a_compose-only_pre-pass_before_bind.adoc[ADR-0010])
and parses only the `management` block:

* *The duplication is bounded and one-directional.* Parsing, schema validation and semantic
  validation still happen once in `ConfigLoader` and `ConfigValidator`; the early pass reads one
  block and emits at most one key.

* *A malformed or absent document degrades silently here.* The loader re-encounters the failure
  moments later and reports it as a located `ConfigError` that fails the boot.

* *An unexpected shape reads as "not explicitly disabled".* A non-map `management` block or a
  non-boolean `enabled` keeps TLS on, the fail-safe direction.

*The source is single-ordinal and projects policy keys only.* Its ordinal sits above the
environment-variable source's, so a deployment variable cannot silently override a policy named in
`gateway.yaml`. That is safe because the projected set contains no deployment-bound key: never a
port, never trust material, and never `quarkus.tls.key-store.*` (populating the default TLS registry
bucket would make the management interface inherit HTTPS through `registry.getDefault()`).
