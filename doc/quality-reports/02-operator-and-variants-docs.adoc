== Cross-Cutting Findings in `doc/user/` and `doc/variants/`

=== 1. Unembedded Existing SVG Diagrams in `doc/resources/diagrams/`

Eleven relevant SVG diagrams already exist in `doc/resources/diagrams/` (created for `doc/architecture/` and `doc/development/`), yet `doc/user/` currently has *zero* `image::` directives (`doc/variants/` has 6). Embedding existing diagrams immediately improves human comprehension in `doc/user/` without duplicating artwork:

* `bff-login-callback-flow.svg` -> embed in `doc/user/bff-session.adoc` and `doc/user/bff-cookie.adoc`
* `bff-cookie-vs-server-session.svg` -> embed in `doc/user/bff-session.adoc` and `doc/user/bff-cookie.adoc`
* `bff-token-refresh-singleflight.svg` -> embed in `doc/user/bff-oidc-common.adoc`
* `route-matching-specificity.svg` -> embed in `doc/user/endpoint-routes.adoc`
* `path-normalization-and-stripping.svg` -> embed in `doc/user/endpoint-routes.adoc`
* `forwarding-header-sanitization.svg` -> embed in `doc/user/endpoint-routes.adoc`
* `websocket-upgrade-and-tunnel.svg` -> embed in `doc/user/endpoint-routes.adoc`
* `inbound-filter-chain.svg` -> embed in `doc/user/edge-security.adoc`

=== 2. Verbatim Duplication Between `bff-session.adoc` and `bff-cookie.adoc` (~480 lines)

`doc/user/bff-session.adoc` (`1,302` lines) and `doc/user/bff-cookie.adoc` (`1,080` lines) were authored as standalone clones. Approximately 480 lines are nearly word-for-word identical across both files:

* OIDC discovery (`oidc_discovery` vs explicit endpoint URLs) and `idp_tls` PEM trust setup (`bff-session.adoc:185–315` vs `bff-cookie.adoc:175–304`)
* Client authentication modes (`client_secret_basic`, `client_secret_post`, `private_key_jwt`) (`bff-session.adoc:395–520` vs `bff-cookie.adoc:367–490`)
* Pushed Authorization Requests (`par.enabled`, `par.require`) and DPoP sender-constrained proofs (`dpop.enabled`) (`bff-session.adoc:521–645` vs `bff-cookie.adoc:491–610`)
* Refresh-token rotation, `refresh_skew`, and `reuse_interval` (`bff-session.adoc:710–830` vs `bff-cookie.adoc:611–698`)
* Return-to origin validation (`allowed_return_to_origins`) and logout (`bff-session.adoc:831–940` vs `bff-cookie.adoc:758–846`)

Extracting `doc/user/bff-oidc-common.adoc` (~350 lines) eliminates this duplication and lets `bff-session.adoc` and `bff-cookie.adoc` focus strictly on their storage model (`mode: server` vs `mode: cookie`).

=== 3. Pre-1.0 Migration Notes and Stale Claims

* *`doc/variants/03-bff-cookie.adoc:17` (Correctness Bug)*: States `"Stateless encrypted-cookie BFF session storage is *planned*..."` even though the rest of `03-bff-cookie.adoc`, `doc/user/bff-cookie.adoc`, and `ADR-0058` document the shipped `mode: cookie` implementation.
* *`doc/user/endpoint-routes.adoc:153–166` (Dangerous Copy-Paste YAML)*: The canonical copy-paste YAML example includes four keys annotated `# INERT today -- accepted by schema, ignored at runtime`. Presenting inert keys in a starter operator template invites misconfiguration.
* *`doc/user/bff-cookie.adoc` (6 Pre-1.0 Migration Blocks)*: Lines `129–158`, `305–366`, `699–720`, `742–757`, `801–826`, and `847–879` narrate how YAML keys changed from earlier `0.2.x` drafts.
* *`doc/user/endpoint-routes.adoc` (Pre-1.0 Migration Blocks)*: Lines `533–554` and `784–792` narrate removed legacy route fields.
* *`doc/user/compose-sample.adoc:739–761`*: Contains a pre-1.0 upgrade warning block for old compose files, plus 3 repeated explanations of the `0.2.4` image tag (`L48–62`, `L212–228`, `L715–738`) and 2 repeated notes on Docker Compose `2.24.4` teardown (`L265–280`, `L810–825`).
