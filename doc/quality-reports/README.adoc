== Scope and Review Objectives

Following the architecture documentation streamlining in PR `#571` (`d9cd9e5f`), this review audits the remaining repository documentation across four groups:

* link:01-root-and-reference-docs.adoc[Group 1 — Root & Top-Level Reference Docs] (`README.adoc`, `doc/README.adoc`, `doc/configuration.adoc`, `doc/security-threat-model.adoc`, `doc/technical_aspects.adoc`, `doc/features-analysis.adoc`, `doc/fapi_status.adoc`, `doc/fapi_next_steps.adoc`, `doc/LogMessages.adoc`, and `doc/quality-report/*.adoc`)
* link:02-operator-and-variants-docs.adoc[Group 2 — Operator Guides & Deployment Variants] (`doc/user/*.adoc` and `doc/variants/*.adoc`)
* link:03-development-and-module-docs.adoc[Group 3 — Contributor Guides & Module Docs] (`doc/development/*.adoc`, `benchmarks/README.adoc`, `benchmarks/doc/*`, `demo-client/README.adoc`, and `demo-client/doc/*`)
* link:04-adr-corpus.adoc[Group 4 — Architectural Decision Records] (`doc/adr/*.adoc` and ADR index parity in `doc/README.adoc`)

Every document is evaluated against six release-readiness criteria:

1. *Correctness, completeness, and consistency* against the current codebase and across sibling documents.
2. *Splitting overly large documents* so no reference or guide acts as a monolithic wall of text.
3. *Adding SVG diagrams where sensible* — prioritizing sequence, flow, swim-lane, state, and decision diagrams over static box diagrams so human readers grasp multi-hop protocols, precedence chains, and failure paths immediately.
4. *Compliance with `engineering-narrative.md`* — three-part arc (concrete problem -> structural response -> honest limit), third-person present tense, actors as subjects, maximum heading depth `<= 3` (`===`), and zero marketing fluff, lecturing prose, or empty filler phrases ("Floskeln").
5. *Overall size reduction* by replacing prose repetition with concise tables, cross-links, and diagrams.
6. *Elimination of duplication, ambiguity, and historical overhead* — removing pre-1.0 deprecation/migration essays, dated audit logs, PR review diaries, and internal implementation class/test inventories from operator-facing and architectural prose.

== Cross-Cutting Findings

=== Pre-1.0 Historical Overhead and Audit Diaries

The single largest source of bloat across the documentation tree is historical narration that violates the repository's Pre-1.0 rules and `engineering-narrative.md`:

* *Pre-1.0 migration and rename essays*: `README.adoc` (`L202–264`), `doc/configuration.adoc` (`L1034–1057`), `doc/user/bff-cookie.adoc` (`L129–158`, `L305–366`, `L699–720`, `L742–757`, `L801–826`, `L847–879`), `doc/user/endpoint-routes.adoc` (`L153–166`, `L533–554`, `L784–792`), and `doc/user/compose-sample.adoc` (`L739–761`) explain removed YAML keys, renamed Quarkus properties, and upgrade paths between `0.1.x` and `0.2.x` snapshots.
* *Dated audit logs, pass-by-pass ledger dumps, and lab notebooks*: `doc/development/test-corpus-integrity.adoc` (`2,836` lines, of which `2,576` lines are completed Pass 1/2/3 audit tables and empty backlogs), `doc/development/build-gate-discipline.adoc` (`680` lines of dated OpenRewrite diffs and refuted macOS kernel hypotheses), `doc/development/integration-test-topology.adoc` (`288` lines of `"=== Diagram check for the ... change"` read-back sections and PR `#408` disposition logs), `doc/development/release-process.adoc` (`110` lines of pre-merge/post-merge execution diaries), `doc/security-threat-model.adoc` (`55` lines of `orbstack` kernel lab notes), and `doc/quality-report/*.adoc` (`2,560` lines of a frozen `2026-08-15` snapshot at `commit b54eb12`).
* *Skill and prompt leaks in committed prose*: `doc/development/README.adoc:402` references `pm-documents:ref-svg-diagrams`; `benchmarks/README.adoc:223` opens with `"Per Clarification 1, no benchmark gates the build"`.

=== Sentence-Level Chattiness and Genre-Voice Misalignment (~8,400 Lines of Compressible Prose)

Even after removing historical blocks and cross-document duplicates, the surviving prose in `doc/configuration.adoc`, `doc/user/*.adoc`, `doc/security-threat-model.adoc`, and `doc/adr/*.adoc` is 35–40% too verbose due to five sentence-level habits that every wave must compress:

1. *Genre-Voice Misalignment (`engineering-narrative` Applied to Lookup Specs and Operator Guides)*:
   Every YAML key in `doc/configuration.adoc` and every setup step in `doc/user/*.adoc` is currently written as an argumentative essay with bolded philosophical thesis sentences. Enforce `reference-spec.md` on `doc/configuration/`, `doc/variants/`, and `doc/LogMessages.adoc` (signature/key, semantics, boundary/default), and `tutorial-walkthrough.md` on `doc/user/` (start state, ordered steps, observable checkpoint).

2. *Rhetorical Lecturing & Negative Preambles ("X is Y, not a licence to Z")*:
   Strip dramatic lecturing that argues against strawman misconfigurations (for example, `doc/user/tls-edge.adoc:83–125` spending 42 lines lecturing on why plain HTTP is not inferred instead of a 6-line rule + refusal table).

3. *Provenance & Test-Harness Chatter Inside Operator Prose*:
   Strip meta-commentary explaining how the author derived a table from source code or how internal ArchUnit tests (`EgressTlsPostureArchTest` in `doc/configuration.adoc:1322–1377`) scan AST call sites.

4. *Patch-by-Patch Archaeology Inside Current-State Sections*:
   Strip chronological accounts of how a control evolved across earlier bugs or ADRs (`"The coverage exception was first written path-geometrically... Before ADR-0047 they were not..."` in `doc/security-threat-model.adoc:415–470`). State only the invariant that holds today.

5. *Prose Enumerations Instead of Flat Tables*:
   Convert multi-clause semicolon paragraphs listing boot refusals, input constraints, or flag interactions (`doc/user/portal.adoc:88–99`, `doc/user/tls-edge.adoc:88–125`, `doc/configuration.adoc`) into compact 3-column tables (`Condition` | `Behavior / Refusal` | `Log ID`).

=== Cross-Document Duplication & Single-Source-of-Truth (SSOT) Matrix

Tracing topics across the entire repository (`doc/configuration.adoc` ↔ `doc/user/*` ↔ `doc/variants/*` ↔ `doc/development/*` ↔ `doc/architecture/*` ↔ `doc/adr/*`) reveals *10 major cross-document duplication clusters* totaling over `12,000` lines of repeated explanations.

The root cause is that `doc/configuration.adoc` currently embeds full multi-page operator tutorials and architecture essays alongside field definitions, while `doc/user/`, `doc/variants/`, and `doc/development/` maintain parallel files with identical filenames (`bff-cookie.adoc`, `bff-session.adoc`, `compose-sample.adoc`, `tls-edge.adoc`, `context-path*.adoc`) that re-explain the same concepts from scratch.

To eliminate cross-document duplication permanently, each layer must enforce a strict Single-Source-of-Truth (SSOT) boundary:

* *`doc/configuration/` (Schema & Field Dictionary)*: Key name, type, default, allowed values, boot validation rule, and a 1-sentence summary with a link to `doc/user/`. Zero multi-paragraph tutorials or architectural rationale.
* *`doc/user/` (Task-Oriented Operator How-To)*: Actionable configuration recipes and operational procedures. Zero Java class names, build-step internals, or duplicated schema tables.
* *`doc/variants/` (PostureDatasheets)*: Compact 1-page (~150-line) posture datasheets (topology SVG + minimal YAML delta + properties summary + links to `doc/user/`). Zero re-explanation of OIDC, PAR, DPoP, or cookie mechanics.
* *`doc/architecture/` (Runtime Design & Invariants)*: Component boundaries, request pipeline stages, and runtime guarantees.
* *`doc/development/` (Contributor Playbooks & Verification Harnesses)*: How to extend code, run test rigs, and maintain fitness functions. Zero repetition of operator guides or architecture docs.
* *`doc/adr/` (Point-in-Time Decision Rationale)*: Context, decision, and trade-offs (`<= 250` lines). Zero inline YAML manuals or code inventories.
