== Principles

Configuration is *static, file-based, and immutable*. It is read once at startup, validated
in full, frozen into immutable value objects, and never mutated at runtime. The gateway
refuses to boot on invalid configuration.

* *Endpoint config is portable; topology is environment-specific.* Route definitions never name
  a concrete *upstream* host; they reference an abstract alias (`APP1`, `KEYCLOAK`, ...) that
  `topology.properties` binds to a real location. A `match.host` matcher is the exception: it
  matches the *inbound* `Host` header (the gateway's own public vhost) and is environment-specific.
* *Deny-by-default at the URL layer.* A request matching no route reaches no upstream, and an
  authentication posture is always written out. Within a matched route the `forward` block chooses a
  filtering posture -- permissive by default, strict by opt-in -- bounded by gateway-owned sets no
  configuration can override (see link:configuration/routing-and-forwarding.adoc#_forward[`forward`]).
* *Endpoint-centric routes*, each dispatched behind the gateway's fixed upstream guard (timeout
  and circuit breaker, link:adr/0064-The_upstream_guard_is_fixed_in_the_gateway_and_a_route_declares_no_circuit_breaker_settings.adoc[ADR-0064]),
  with composable, bounded matchers (path, method, host, header).
* *Three-mode forward filtering* (positive-list, negative-list, or forward-all per dimension),
  bounded by gateway-owned never-forward sets.
* *Alias -> URL indirection*: an environment variable supplies or overrides a value only through an
  explicit in-file `${VAR}` placeholder, never by automatic lookup
  (link:adr/0004-topology-indirection.adoc[ADR-0004]).
* *Declarative only*: no rule language and no runtime mutation API.

The provenance of these patterns is recorded in the link:features-analysis.adoc[Feature Analysis]
and the ADRs.

== Configuration Layout

Configuration is three kinds of artifact:

[cols="1,3"]
|===
| Artifact | Purpose

| `gateway.yaml`
| *Global* settings: schema version, TLS, security-response headers, filter defaults, the
  link:user/anchors.adoc#_anchors[`anchors`] (namespace-scoped policy), the `forwarded`-header policy, and the
  `oidc` block (BFF variants). No routes.

| `endpoints/*.yaml`
| *One file per endpoint* (a service, host, app or logical group): its routes and, when an enabled
  endpoint has at least one proxy route, one `base_url` *alias* (see
  link:#_endpoint_identity[`endpoint`]). Never contains a real *upstream* host; write an inbound
  `match.host` as a `${VAR}` placeholder.

| `topology.properties`
| Maps each `base_url` alias to one concrete URL, overridable per alias through an explicit
  `${VAR}` placeholder. The *only* file that changes between environments.
|===

[source,text]
----
config/
  gateway.yaml              # global settings
  endpoints/
    app1.yaml               # base_url: APP1     -> routes for /api/orders ...
    keycloak.yaml           # base_url: KEYCLOAK -> routes for /auth, /token
  topology.properties       # APP1=..., KEYCLOAK=...   (explicit ${VAR} placeholders let env vars override)
----

The configuration directory is selected by the `sheriff.config.dir` property (a Quarkus
configuration property; default `config`). Under it, `gateway.yaml` and `topology.properties`
are read by exact name, and every *`.yaml`* file directly under `endpoints/` is loaded as an
endpoint file in filename-sorted order. A `.yml` file there *fails the boot* with a request to
rename it to `.yaml`; files with any other extension, and nested subdirectories, are ignored.

*An endpoint file is named after the `id` it declares*: `endpoints/<id>.yaml` holds the endpoint
whose `endpoint.id` is `<id>`. A mismatch *fails the boot* (and the offline
link:user/offline-config-validation.adoc[`--validate-config`] check) with one error at
`/endpoint/id` of the loaded file, naming both values and the rename that fixes it. Every later
configuration error therefore names the file that was read.

== Loading, Resolution and Validation

* `gateway.yaml`, every file under `endpoints/`, and `topology.properties` are read once at
  startup.
* Each `base_url` alias of an *enabled* endpoint is *resolved* against the topology and *decomposed
  once* into `{scheme, host, port, base-path}` (link:adr/0004-topology-indirection.adoc[ADR-0004],
  link:user/environment-variable-overrides.adoc#_topology_and_endpoint_enablement[Topology]). A
  disabled endpoint's alias is not resolved (see link:#_endpoint_identity[`enabled`]).
* The document set is validated as a whole; unknown keys, unknown `version`, an unresolved alias
  of an enabled endpoint, a malformed topology URL, or a route referencing a missing endpoint all
  *fail the boot*.
* Secrets are never inlined: they are `${ENV_VAR}` references, so the config artifacts are safe to
  commit. Topology values may be literal (they are locations, not secrets).
* *Environment override placeholders*
  (link:adr/0004-topology-indirection.adoc#_topology_override_placeholder[ADR-0004]) are resolved
  once, before schema validation, uniformly across `gateway.yaml`, `endpoints/*.yaml` and
  `topology.properties`:
+
[cols="1,3"]
|===
| Form | Behaviour

| `${NAME}`
| Required: an unset variable fails the boot.

| `${NAME:-default}`
| Optional: the literal `default` (everything between the first `:-` and the closing brace) applies
  when the variable is unset; an environment value wins over it.
|===
+
`NAME` matches `[A-Za-z_][A-Za-z0-9_]*`; several placeholders may appear in one scalar; there is *no
nesting and no escape syntax*, and a scalar carrying a `${` that is not a well-formed placeholder
*fails the boot*. The `TOPOLOGY_<ALIAS>` / `ENDPOINT_<ID>_ENABLED` names used in this reference are
conventional variable names written inside such placeholders; there is no implicit lookup.
* On any validation error the process exits non-zero and logs the offending file/alias; it never
  starts a degraded gateway.

== Schemas

Both configuration artifacts are validated against bundled *JSON Schema* documents (Draft
2020-12) before binding, so a structurally malformed file is rejected with a precise
file-and-JSON-pointer error before any immutable value object is built:

[cols="1,3"]
|===
| Schema | Validates

| `schema/gateway.schema.json`
| The global `gateway.yaml` document -- `version` (the only required key), `metadata`, `tls`,
  `management`, `security_headers`, `security_defaults`, `allowed_methods`, `anchors`,
  `upstream_defaults`, `asset_defaults`, `forwarded`, `edge_hardening`, `enumeration_detection`,
  `threat_classification`, `token_validation`, `cookies` and `oidc`.

| `schema/endpoint.schema.json`
| A single `endpoints/*.yaml` file -- the `endpoint` block (`id`, `enabled`, `base_url`,
  `anchor`, `auth`, `scopes`, `allowed_methods`, `upstream_defaults`, `security_filter`,
  `forward`, `cookies`, `catalog`) and its `routes[]`, each route's `id`, `protocol`, `anchor`,
  `match`, `auth`, `security_filter`, `forward`, `cookies`, `keep_identity_headers`, `upstream`,
  `asset`, `redirect`, `websocket` and `rate_limit`. The WebSocket-route `websocket` block holds
  `allowed_origins` and `idle_timeout_seconds`; `rate_limit` is planned, not implemented, and
  never causes a `429` -- see link:configuration/security-and-edge-hardening.adoc#_rate_limit[`rate_limit`].
|===

Both schemas set `additionalProperties: false` at *every* object level, so an *unknown key* fails
the boot. The schemas are the *structural* gate only; the cross-cutting rules (`id` uniqueness,
policy-block resolution per link:user/anchors.adoc#_policy_block_resolution[Policy-block resolution],
`allowed_methods` membership, alias resolvability, `base_url`-only-with-a-proxy-route, one terminal
action, the `redirect` open-redirect review, same-prefix / same-exact-path disjointness) are listed
under link:configuration/validation-rules.adoc#_configuration_validation_rules_summary[Configuration Validation Rules].

Boot validation runs in three stages; each collects all of its violations in one pass, reports them
together, and stops the boot when it fails:

[cols="1,3"]
|===
| Stage | Behaviour

| 1. Load (schema)
| Runs first. A failure stops the pass.

| 2. Topology resolution
| Runs before the validator (link:adr/0009-asymmetric-alias-resolution-failure.adoc[ADR-0009]).
  Reports `ApiSheriff-200` entries followed by the `ApiSheriff-201` summary. Each alias is attempted
  at most once per pass (even when shared by several endpoints or by an endpoint and a
  `passthrough_sni` target) and yields at most one entry (file `topology.properties`, the alias as
  pointer) for its first failure: undefined alias of an enabled endpoint, failed placeholder
  substitution (the message names every unset variable of that value), or a URL that is malformed,
  not absolute or not `http`/`https`. An unreadable `topology.properties` is a single entry with an
  empty pointer. A failure here defers the validator's findings until the topology resolves.

| 3. Validator
| Reports every rule violation together. An *undefined* `tls.passthrough_sni` target is reported
  here -- unless an enabled endpoint uses the same alias as its `base_url`, in which case stage 2
  refuses it. A *defined* `passthrough_sni` target whose placeholder fails or whose URL is malformed
  fails stage 2.
|===

The offline check `--validate-config` reports the same entries without booting -- see
link:user/offline-config-validation.adoc[Offline Configuration Validation].

== Gateway Configuration (`gateway.yaml`)

[source,yaml]
----
version: 1                         # config schema version; unknown values are refused

metadata:
  config_version: "2026-07-10.1"   # audit stamp only (see "Configuration Mode")

tls:                               # TLS POLICY for the terminated listener. Neutral names only:
                                   #   ports and certificate/key material stay deployment-supplied
                                   #   and never appear here (ADR-0025). One named exception:
                                   #   mtls.client_ca below REFERENCES a trust anchor by path --
                                   #   see "the client_ca carve-out"
  min_version: "1.3"
  cipher_suites: []                # OPTIONAL allowlist, e.g.
                                   #   [TLS_AES_256_GCM_SHA384, TLS_AES_128_GCM_SHA256].
                                   #   Omit/empty => the runtime's own suite selection
  alpn: [h2, http/1.1]             # HTTP/2 (also carries gRPC) + HTTP/1.1
  passthrough_sni: {}              # SNI hostname -> topology alias, relayed at L4 without
                                   #   decryption, e.g. { legacy.example.com: LEGACY }
                                   #   ONE variable carries the WHOLE map: "${VAR}" with
                                   #   VAR=host1=ALIAS1,host2=ALIAS2 (split on the first '=')
  mtls:
    enabled: false
    client_ca: /etc/sheriff/ca.pem

egress_tls:                        # Egress-TLS policy for the legs the gateway DIALS (ADR-0040,
                                   #   ADR-0045). Disjoint from the `tls` block above, which governs
                                   #   the certificate the gateway PRESENTS to clients. Global rather
                                   #   than per route because these bind at egress client
                                   #   construction. Each key reaches only the leg it is named for.
                                   #   Omit the block, or any key in it, to take the secure defaults
                                   #   shown -- an omitted key never resolves to false.
  upstream_verify_hostname: true   # default true. false relaxes HOSTNAME MATCHING ONLY: an upstream
                                   #   whose certificate does not chain to a trusted anchor is still
                                   #   refused, and passthrough is untouched (never decrypted)
  jwks_verify_hostname: true       # default true. false relaxes HOSTNAME MATCHING ONLY on the JWKS
                                   #   back-channel: an IdP whose certificate does not chain to a
                                   #   trusted anchor is still refused. Refused at boot when an
                                   #   http-sourced issuer also names jwks.tls_profile (ADR-0041)
  upstream_tls_profile: corporate-upstream   # OPTIONAL logical trust profile for terminated upstream
                                   #   dials. Names a profile, never material: the deployment binds
                                   #   the anchors via quarkus.tls.<name>.trust-store.* (ADR-0011).
                                   #   REPLACES the client's anchors rather than adding to them.
                                   #   Omit to keep the JVM default trust store
  oidc_verify_hostname: true       # default true. false relaxes HOSTNAME MATCHING ONLY on the BFF
                                   #   OIDC back-channel (discovery, pushed authorization request,
                                   #   code exchange, refresh, revocation): an IdP whose certificate
                                   #   does not chain to a trusted anchor is still refused. Refused
                                   #   at boot together with oidc_tls_profile (ADR-0045)
  oidc_tls_profile: corporate-idp  # OPTIONAL logical trust profile for the BFF OIDC back-channel.
                                   #   Names a profile, never material (ADR-0011). REPLACES the JVM
                                   #   default trust store on that leg. Omit to keep the JVM default

management:                       # TLS policy for the management interface (health/metrics on
                                   #   their own port). POLICY ONLY -- this block declares NO
                                   #   port; the port is deployment-bound (see "management")
  tls:
    enabled: true                  # HTTPS is the default and the shipped posture. false takes
                                   #   the WHOLE management surface to plain HTTP and emits a
                                   #   loud boot WARN (ApiSheriff-115)

security_headers:                  # response-header middleware (global block). Seeded onto every
                                   #   response; once a route is selected, an anchor block REPLACES
                                   #   it wholesale for that anchor's routes (see "security_headers")
  hsts: { max_age: 31536000, include_subdomains: true }
  content_type_nosniff: true
  frame_deny: true
  content_security_policy: "default-src 'self'"   # served VERBATIM; omit => no CSP header
  header_modes:                    # OPTIONAL per-header precedence vs. the origin's own header:
    content_security_policy: default   #   set (absent key, overwrite) | default (origin value kept)
  cors:                            # GLOBAL ONLY -- refused inside an anchor block. Disabled unless
                                   #   configured; a cross-origin SPA (see
    enabled: true                  #   oidc.session.csrf below) needs this enabled WITH
    allowed_origins: [https://app.example.com]   # credentials, or the browser blocks the calls
    allowed_methods: [GET, POST]
    allowed_headers: [content-type]
    allow_credentials: true

security_defaults:                 # baseline inbound filter mode; overridable per anchor, endpoint
                                   #   or route by a security_filter block
  profile: strict                  # strict | paranoid | lenient | minimal   (omitted block => strict)
                                   # 'paranoid' is 'strict' PLUS content block-lists -- it rejects
                                   # 'file'/'path'/'url' parameter names and sensitive path segments
                                   # 'minimal' is a PARTIAL disable, not an off switch:
                                   # see "The `minimal` mode" below for the closed definition
  allow_get_with_content_length_body: false   # OPTIONAL, default false. Admits a Content-Length-
                                   #   framed body on GET (for upstreams like Elasticsearch
                                   #   _search). PARTIAL: Transfer-Encoding on GET stays REJECTED
                                   #   unconditionally, and HEAD is unaffected on every leg.
                                   #   See "The `GET`-body opt-in" below.
  allow_extended_ascii: true       # OPTIONAL, omitted => the profile decides (strict: rejected,
                                   #   lenient: admitted). Gateway-wide override admitting non-ASCII
                                   #   header values and Latin-1 characters in paths and parameter
                                   #   values. C1 controls, header names and cookies stay ASCII-only.
                                   #   See "The extended-ASCII override" below.
  uniform_not_found: true          # OPTIONAL, default true. A rejection raised after route
                                   #   selection and before the trust boundary is answered to the
                                   #   caller as the unrouted 404, on a timing floor; the true
                                   #   event stays in sheriff_errors_total{event}. false restores
                                   #   the honest 401/400/405/413/403. See "The uniform 404" below.

allowed_methods: [GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS]   # positive HTTP-verb allowlist
                                   #   (global default). An anchor or endpoint may REPLACE this
                                   #   wholesale -- the nearest declared scope wins (see
                                   #   "Policy-block resolution" in user/anchors.adoc).
                                   #   A routed request whose method is not in the EFFECTIVE list
                                   #   is rejected 405 -- answered as the unrouted 404 while
                                   #   security_defaults.uniform_not_found is on, the true event
                                   #   METHOD_NOT_ALLOWED staying in sheriff_errors_total{event}.
                                   #   TRACE and CONNECT are never permitted and
                                   #   cannot be listed. Omit => the standard set shown here.

cookies:                           # OPTIONAL gateway-wide cookie policy (see "cookies"); an anchor,
  allow: none                      #   endpoint or route block REPLACES it wholesale.
                                   #   none | all | [NAME, ...] -- all is REFUSED at this scope.
                                   #   Omit => none: no browser cookie reaches an upstream and no
                                   #   upstream Set-Cookie reaches the browser. The gateway's own
                                   #   cookies cross under no block

anchors:                           # OPTIONAL namespace-scoped policy (see "Anchors" in
  api:                             #   user/anchors.adoc); each anchor OWNS a disjoint path
    path_prefix: /api              #   namespace and carries the policy floor for every route
                                   #   inside it
    type: proxy                    # MANDATORY classification axis (proxy | bff | asset); see
                                   #   "Type and access axes" in user/anchors.adoc. Unrelated to
                                   #   tls.passthrough_sni.
    access: authenticated          # MANDATORY audience axis (public | authenticated); a bearer
                                   #   floor is what `authenticated` requires
    auth: { require: bearer }      # every /api route presents a bearer token; a member route
                                   #   may replace this block but never weaken it to `none`
    security_filter: { profile: strict }
    security_headers:              # REPLACES the global block for /api routes -- no merge: a key
                                   #   not restated here (content_security_policy, header_modes)
                                   #   is absent under /api. No `cors` key is accepted here
      hsts: { max_age: 31536000, include_subdomains: true }
      content_type_nosniff: true
      frame_deny: true
  app:
    path_prefix: /app
    type: bff                      # a bff surface MUST declare access: authenticated
    access: authenticated
    auth: { require: session }     # the BFF surface: mediated OIDC session per the oidc block.
                                   #   Its routes live under /app; the reserved OIDC paths below
                                   #   (/bff/*) are not an anchor and need none
  static:                          # an asset surface (see "Asset terminal action" in
                                   #   user/endpoint-routes.adoc)
    path_prefix: /static
    type: asset
    access: public                 # a public anchor declares NO auth block (public is the
                                   #   absence of auth); an auth block here fails the boot

asset_defaults:                    # OPTIONAL. ADD-ONLY extension of the gateway's built-in asset
                                   #   content-type map. Omit the block to let the built-in map
                                   #   govern alone.
  content_types:                   # extension (lowercase, no dot) -> Content-Type
    webmanifest: application/manifest+json   # an extension the gateway does NOT map
                                   #   An entry naming a BUILT-IN extension (html, css, js, svg,
                                   #   png, ... -- 21 in total) is REFUSED AT BOOT, naming the
                                   #   offending extension. The built-ins are immutable because
                                   #   remapping one -- svg away from image/svg+xml, or any
                                   #   built-in to text/html -- is a stored-XSS lever on a
                                   #   security gateway.

forwarded:                         # resolved by cui-http (de.cuioss.http.forwarded)
  trusted_proxies: [10.0.0.5/32, 10.0.0.6/32]   # MANDATORY; the exact proxy addresses --
                                   #   keep as narrow as possible; empty => forwarding
                                   #   headers are never trusted; TCP peer is the client.
                                   #   An entry broader than /16 (IPv4) or /48 (IPv6) boots with
                                   #   a WARN (ApiSheriff-102); a /16 or /48 boots silently as a
                                   #   chosen exposure, not a safe one; trust-all is refused
                                   #   (ADR-0044)
                                   #
                                   # OR, supplied whole from the environment:
                                   #   trusted_proxies: "${SHERIFF_TRUSTED_PROXIES}"
                                   #   with SHERIFF_TRUSTED_PROXIES=10.0.0.5/32,10.0.0.6/32
                                   #
                                   #   ONE variable carries the WHOLE list, comma-separated
                                   #   and stripped, so the number of proxies is fixed by the
                                   #   deployment rather than by this file -- which is the
                                   #   point, since the trusted set differs per environment
                                   #   while the mounted document is copied unchanged.
                                   #   Use the BARE ${VAR}: a ${VAR:-default} form would let
                                   #   the gateway boot with a trust set nobody chose, so an
                                   #   empty resolution FAILS THE BOOT instead. Writing an
                                   #   explicit [] here still means "trust no proxy" and
                                   #   stays valid -- the refusal is of an emptied
                                   #   SUBSTITUTION, never of a list you wrote empty.
                                   #   A substituted range meets the SAME breadth rules as a
                                   #   literal one -- no stricter refusal -- and no review of
                                   #   this file ever sees it, so the WARN is its only signal.
                                   #   The PRESENCE of the forwarded block still requires a
                                   #   file edit; only the value is environment-supplied.
  emit: x-forwarded               # x-forwarded (default) | both (adds RFC 7239 Forwarded)

edge_hardening:                    # OPTIONAL admission budget for the public data-plane edge.
                                   #   Omit the block, or either key, to take the defaults shown.
  admission_cap: 2048              # max concurrently in-flight requests across the whole edge;
                                   #   a request beyond it is refused 503. Minimum 1.
  websocket_relay_cap: 512         # max concurrently ESTABLISHED WebSocket relays. A sub-budget
                                   #   acquired IN ADDITION TO the general permit above, never
                                   #   instead of it, because a relay holds its permit for the
                                   #   connection's whole lifetime rather than one round-trip.
                                   #   Minimum 1, and must not exceed admission_cap -- a larger
                                   #   value could never bind. Omitting this key alone takes a
                                   #   QUARTER of the effective admission_cap (>= 1), so lowering
                                   #   admission_cap alone stays valid. See "Sizing the WebSocket
                                   #   relay budget" in the protocol-routes guide.
                                   # NO KEY for the held-answer sub-budget: an answer held back on
                                   #   a timer -- the uniform 404 waiting for its timing floor, the
                                   #   delay action of enumeration_detection -- hands its general
                                   #   permit back while it waits and takes a held permit instead.
                                   #   There are a QUARTER of the effective admission_cap of them
                                   #   (>= 1), so admission_cap scales both. When all are taken, a
                                   #   further answer that would wait is a bare 503, written no
                                   #   earlier than the floor's release time (at once when
                                   #   uniform_not_found is off) and alike for every
                                   #   route and caller, and it waits under its own general
                                   #   permit until then; held answers keep no general permit, so
                                   #   those stay free for requests that are served.

enumeration_detection:             # OPTIONAL per-source scan detection. Omit the block, or any
                                   #   key, to take the defaults shown: detection RUNS and a trip
                                   #   changes no answer.
  enabled: true                    # false builds no detection at all
  threshold: 100                   # weighted recon rejections at which a source trips. Minimum 1.
  window_seconds: 60               # a full threshold drains in this many seconds. Minimum 1.
  action: observe                  # observe (default) | delay | block. observe only logs the trip
                                   #   (ApiSheriff-141) and meters it. delay holds the source's
                                   #   rejection answers (and answers 429 once its share of the
                                   #   held-answer sub-budget is used up); block answers it 429
                                   #   before admission.
                                   #   Switch only once a source address is ONE client: behind a
                                   #   NAT or an untrusted load balancer it is every client -- set
                                   #   forwarded.trusted_proxies first.
  block_seconds: 60                # how long a source stays blocked under block. Minimum 1.
  delay_millis: 2000               # how long rejection answers are held under delay. 1..10000.

threat_classification:             # OPTIONAL per-source threat score. Omit the block, or any key,
                                   #   to take the defaults shown: classification RUNS, and its
                                   #   ALERT (ApiSheriff-143) changes no answer -- observe only.
  enabled: true                    # false builds no classifier at all
  threshold: 100                   # weighted score at which a source raises its ALERT. Minimum 1.
  window_seconds: 300              # a full threshold drains in this many seconds. Minimum 1.
  weights:                         # weight per rejection category. Minimum 0 each.
    input_validation: 10           #   malformed or injection-shaped requests
    routing: 1                     #   unrouted addresses and wrong methods
    authentication: 2              #   missing or invalid bearer tokens
    authorization: 2               #   missing scopes, CSRF and origin refusals
    recon_trip: 50                 #   a trip of enumeration_detection; refused when it is disabled

token_validation:                  # offline bearer validation (routes with auth.require: bearer)
  issuers:                         # one entry per accepted identity provider
    - name: main
      issuer: https://idp.example.com/realms/main   # expected iss claim
      audience: api-sheriff                          # expected aud claim
      jwks:
        source: http               # http | file
        url: https://idp.example.com/realms/main/protocol/openid-connect/certs
        # file: /etc/sheriff/jwks.json   (air-gapped deployments)
        # allowed_egress_hosts: [idp.internal]   # SSRF egress allowance. Absent/empty DERIVES it:
                                   #   the jwks.url host (port dropped) is the one host exempted
                                   #   from the private-address refusal. A non-empty list is
                                   #   AUTHORITATIVE, host-exact, never merged with the derived
                                   #   host; declare it to pin the allowance (GW-05). A blank or
                                   #   host:port entry is refused at boot
        # tls_profile: corporate-idp             # logical trust profile; OMIT for a public-CA
                                   #   IdP. Names trust anchors without carrying them; the
                                   #   deployment binds the name. See "Trust profiles" below.
        refresh_interval_seconds: 600   # OPTIONAL, source: http only. Background re-fetch of the
                                   #   key set. 60..86400; omitted => 600
        key_rotation_grace_period_seconds: 300   # OPTIONAL, source: http only. How long a replaced
                                   #   key set keeps verifying its own tokens. 0..3600; omitted =>
                                   #   the token library's default (300)
        unknown_kid_refresh_window_seconds: 30   # OPTIONAL, source: http only. A token naming an
                                   #   unknown key id triggers at most ONE key-set refresh per
                                   #   issuer per window. 5..3600; omitted => 30. All three keys
                                   #   are REFUSED AT BOOT on source: file. See "Key rotation and
                                   #   the refresh cadence" below.

oidc:                              # only used by the BFF variants (2 and 3)
                                   # Each listed OIDC endpoint path (callback, login, user_info,
                                   #   logout, its return leg, back-channel, step-up, client JWKS) is
                                   #   a RESERVED path: an exact-match carve-out resolved AHEAD of
                                   #   the route table, on the OIDC host (the host of redirect_uri)
                                   #   -- except back-channel and client JWKS, which are reserved on
                                   #   EVERY host. A reserved path is not an anchor -- it claims that
                                   #   one path and nothing beneath it. Redirect DESTINATIONS such as
                                   #   login.default_return_url and logout.final_redirect are NOT
                                   #   reserved. The /bff/* spelling is a naming convention nothing
                                   #   validates; any canonical path works
  issuer: https://idp.example.com/realms/main
  # back_channel_origin: https://idp.internal:8443   # OPTIONAL. Where the GATEWAY reaches the IdP.
                                   #   Transport, not identity: issuer stays the one identity every
                                   #   check compares against and the browser keeps the advertised
                                   #   endpoints; only discovery, the pushed authorization request,
                                   #   code exchange, refresh and revocation are sent to this origin.
                                   #   An origin only (scheme, host, optional port), https unless
                                   #   back_channel_allow_insecure_http: true (ADR-0069)
  # allowed_egress_hosts: [idp.internal]   # OPTIONAL. Hosts the GATEWAY may dial although they resolve
                                   #   to a private or loopback address, which is refused by default.
                                   #   Host-exact, no port; nothing is derived from issuer or
                                   #   back_channel_origin, so an IdP on a private network needs this
                                   #   (ADR-0082)
  client_id: api-sheriff
  client_authentication:           # private_key_jwt client authentication (the default)
    key_file: /etc/sheriff/keys/client-auth.pem   # PEM file on a mount: one unencrypted PKCS#8
                                   #   PRIVATE KEY block and one PUBLIC KEY block. RSA (>= 2048
                                   #   bits, signs PS256) or EC P-256 (signs ES256). OPTIONAL --
                                   #   omit to generate a key on startup (single node only)
    jwks_path: /bff/jwks           # OPTIONAL; default /bff/jwks. An unauthenticated GET here
                                   #   publishes the client-authentication public key (reserved
                                   #   path, matched on EVERY host: the IdP dials it
                                   #   server-to-server). Register its https URL at the IdP as
                                   #   the client's key-set URL. With client_secret configured
                                   #   the path stays reserved and answers 404
  # client_secret: ${SHERIFF_CLIENT_SECRET}   # selects client-secret authentication, which is
                                   #   not FAPI 2.0 conformant and may weaken security. Refused
                                   #   at boot together with client_authentication.key_file
  sender_constraint:               # DPoP: every access token is bound to this key, in both
                                   #   client-authentication modes; a token response that is not
                                   #   bound to it is refused
    key_file: /etc/sheriff/keys/dpop.pem   # PEM file on a mount, same format and key types as
                                   #   client_authentication.key_file. OPTIONAL -- omit to
                                   #   generate a key on startup (single node only). A separate
                                   #   key here is never published at jwks_path
  scopes: [openid, profile]        # REQUESTED on every login and joined into every route's
                                   #   needed set (bearer AND session routes hold the caller to
                                   #   it); endpoints add their own via endpoint.scopes, never
                                   #   remove these.
                                   #   Each entry is an RFC 6749 scope-token (printable ASCII,
                                   #   no space, " or \) -- anything else is refused at load
  redirect_uri: https://gw.example.com/bff/callback
                                   # register at the IdP as a plain GET redirect target: the
                                   #   gateway drives response_mode=query (fixed in code, no knob)
  login:
    path: /bff/login               # gateway-owned login-initiation entry point (reserved path)
    default_return_url: /          # post-login landing when a login carries no usable target;
                                   #   same-origin with redirect_uri (boot-checked); default /
  user_info:
    path: /bff/session             # gateway-served curated identity view (reserved path)
    allowed_claims: [sub, name, email]   # operator allowlist; empty (default) discloses nothing
    default_view: [sub, name]      # returned when the caller requests no explicit claims;
                                   #   every entry must lie within allowed_claims
  logout:
    path: /bff/logout              # gateway-served; triggers RP-initiated logout at the IdP
    post_logout_redirect_uri: https://gw.example.com/bff/logout/return   # gateway-owned return
                                   #   leg, pre-registered, exact match; verifies the logout state
    final_redirect: https://app.example.com/   # where the browser lands after verification
    backchannel_path: /bff/backchannel   # back-channel receiver (mode: server only)
  session:                         # NOTE: exhibit shows the fields of BOTH modes; store is
                                   #   server-mode-only, key_file cookie-mode-only
    mode: cookie                   # cookie (Variant 3) | server (Variant 2)
    store: memory                  # REQUIRED for server mode; memory is the only initial option
    max_sessions: 10000            # server mode only: upper bound on concurrently stored
                                   #   sessions -- a DoS guard on the in-memory store. Reaching
                                   #   the bound sweeps the expired sessions and admits the login
                                   #   if that freed a slot
    cookie_name: __Host-sheriff    # OPTIONAL, both modes; default __Host-sheriff-session. REFUSED AT
                                   #   BOOT unless a __Host--prefixed RFC 9110 token distinct from
                                   #   the gateway-owned __Host-sheriff-binding / -logout cookies
    key_file: /run/secrets/session.key  # cookie mode only (AES-256-GCM); OPTIONAL -- a file holding
                                   #   one line of base64 decoding to 32 bytes (openssl rand -base64
                                   #   32 > session.key). A location, not a secret. Omit to generate
                                   #   a key on startup (sessions die on restart). REFUSED in server mode
    max_cookie_size: 4019          # cookie mode only: sealed cookie-VALUE size budget in bytes.
                                   #   40..8192, default 4019. Drives BOTH the seal budget and the
                                   #   gateway's pre-route Cookie header-value cap
                                   #   A budget whose emitted header passes ~4096 still boots, but
                                   #   warns (ApiSheriff-124): RFC 6265's ~4096 is a HEADER budget
                                   #   (name + value + attributes), and the gateway derives this
                                   #   cookie's overhead from the configured cookie_name and
                                   #   ttl_seconds -- 77 bytes under the defaults, making 4019 the
                                   #   largest default-configuration value budget a browser is
                                   #   obliged to keep. Above it the browser drops it silently
                                   #   The warning reads the EFFECTIVE budget, so a longer
                                   #   cookie_name or a wider ttl_seconds is caught even with
                                   #   this key omitted
    ttl_seconds: 3600              # absolute session lifetime from login
    csrf:
      trusted_origins: [https://app.example.com]   # app origins allowed on unsafe methods;
                                   #   defaults to the origin of redirect_uri
    refresh:
      enabled: true
      leeway_seconds: 30           # refresh this long before expiry
      on_failure: reauthenticate   # reauthenticate | reject
  step_up:
    enabled: true                  # RFC 9470 upstream-challenge leg
    honor_upstream_challenge: true
    path: /bff/step-up             # OPTIONAL gateway-served step-up entry point (reserved path):
                                   #   widens a LIVE session for the route behind its returnUrl.
                                   #   Named as step_up_url in a session route's 403. Independent
                                   #   of the two keys above

portal:                            # OPTIONAL application portal; omitted => off, no path reserved
                                   #   (see "portal" below and the portal guide)
  path: /                          # EXACT, host-independent reserved path, answered BEFORE the
                                   #   route table -- may claim the context root next to prefix
                                   #   routes. Refused at boot when not canonical, when equal to a
                                   #   reserved OIDC path, or when equal to an enabled exact route
  title: Example Corp Applications # page title; always HTML-escaped
  template_dir: /etc/sheriff/portal   # OPTIONAL directory holding an operator portal.html; omit
                                   #   => the built-in, CSS-free template. Parsed at boot; the
                                   #   template language is defined in the portal guide
  cache_seconds: 60                # OPTIONAL, default 0: max-age of a session-free page. A page
                                   #   for an authenticated session and every error page are no-store
  error_pages: false               # OPTIONAL, default false: render HTML-eligible gateway errors
                                   #   through the template when Accept lists text/html
                                   #   EXPLICITLY; status unchanged, origin responses never replaced

[[_endpoint_identity]]
=== `endpoint` (identity and enablement)

Every `endpoints/*.yaml` file declares exactly one `endpoint` block. Its identity and
enablement fields:

[cols="1,3"]
|===
| Field | Meaning

| `id`
| *Mandatory.* Pattern `[a-z][a-z0-9-]*`. Labels the endpoint in logs and metrics and names its
  file (`endpoints/<id>.yaml`). Must be unique across all endpoint files (in one file or across
  files); a duplicate *fails the boot*. Independent of route-`id` uniqueness.

| `enabled`
| *Optional*, *default `true`*. When `false` the endpoint is *inert*: its routes are not merged into
  the route table (their paths answer the ordinary `404`), it takes no part in the disjointness and
  passthrough-collision checks, and its `base_url` alias need not resolve. It is still
  schema-validated. Per-environment override through an in-file placeholder, e.g.
  `enabled: ${ENDPOINT_ORDER_API_ENABLED:-true}`
  (link:adr/0004-topology-indirection.adoc#_topology_override_placeholder[ADR-0004],
  link:user/environment-variable-overrides.adoc#_topology_and_endpoint_enablement[topology]); by
  convention `<ID>` is the upper-cased `id` with hyphens mapped to underscores.

| `base_url`
| A topology alias (link:user/environment-variable-overrides.adoc#_topology_and_endpoint_enablement[Topology],
  link:adr/0004-topology-indirection.adoc[ADR-0004]). *Mandatory exactly when an enabled endpoint
  carries a proxy route* (a route declaring neither `asset` nor `redirect`); omitted by an endpoint
  of asset and redirect routes only. A disabled endpoint is exempt: it may omit `base_url` while
  carrying proxy routes and may name an unresolvable alias. See
  link:user/endpoint-routes.adoc#_base_url_only_with_proxy_routes[`base_url` is mandatory only with a
  proxy route].
|===

The endpoint's other fields: `anchor` (link:user/anchors.adoc#_anchors[Anchors], the normative
reference for the `anchors` block and the `anchor` membership field),
`auth` (link:configuration/authentication-and-oidc.adoc#_auth[`auth`]),
`scopes` (link:configuration/authentication-and-oidc.adoc#_endpoint_scopes[`endpoint.scopes`]),
`catalog` (link:#_endpoint_catalog[`endpoint.catalog`]),
`allowed_methods` (link:configuration/routing-and-forwarding.adoc#_allowed_methods[`allowed_methods`]),

`security_filter` (link:configuration/security-and-edge-hardening.adoc#_security_filtering[`security_filter`]),
`forward` (link:configuration/routing-and-forwarding.adoc#_forward[`forward`]),
`cookies` (link:configuration/routing-and-forwarding.adoc#_cookies[`cookies`]) and
`routes` (link:user/endpoint-routes.adoc#_route_ordering[Route ordering] and the per-route fields).

[[_portal]]
=== `portal`

The application portal (link:user/portal.adoc[operator guide],
link:adr/0053-Portal_templates_render_on_a_standalone_Qute_engine_and_escape-bypass_constructs_are_refused_at_boot.adoc[ADR-0053]).
An optional `gateway.yaml` block. Omitted: the portal is off and no path is reserved. Declared: the
gateway reserves one exact, host-independent path and answers it with an HTML overview of every
enabled endpoint that declares an link:#_endpoint_catalog[`endpoint.catalog`] block. Unknown keys are
refused by the schema.

[cols="1,3"]
|===
| Field | Meaning

| `path`
| *Mandatory* string with a leading `/` (schema). The exact request path the portal answers, on
  *any* `Host`, compared by exact string equality with the canonical request path (a trailing-slash
  or prefix variant never matches). Answered after the pre-route checks and the reserved OIDC paths
  and *before* the route table, so it may claim the context root (`/`) next to prefix routes. `GET`
  renders the page, `HEAD` answers the same headers with an empty body, any other method is `405`
  with `Allow: GET, HEAD`. Boot refusals, each `ApiSheriff-200` at `/portal/path`:
+
* not canonical (a `//`, a dot segment, a `?` or `#`, a percent-encoded separator, or anything the
  URL path review refuses);
* equal to a reserved OIDC path (callback, logout, logout return, back-channel logout, user-info,
  login, step-up, client JWKS), compared host-independently;
* equal to the exact `match.path` of an *enabled* endpoint's route.

| `title`
| *Mandatory* string, at least one character. Rendered into the template as `title` and always
  HTML-escaped.

| `template_dir`
| *Optional* string. A directory holding an operator-authored `portal.html`, which replaces the
  built-in template. It is read and parsed once at boot, and a template the boot refuses aborts the
  start with `ApiSheriff-202`. The template language is defined in the operator guide, in one place:
  link:user/portal.adoc#_qute_subset[the supported Qute subset] and
  link:user/portal.adoc#_template_refusals[when the boot refuses a template]. Omitted: the built-in
  template, which carries no stylesheet and no script.

| `cache_seconds`
| *Optional* integer, minimum `0`, *default `0`*. The `Cache-Control: max-age` of a portal page that
  carries no session data. With an active BFF runtime such a page also carries `Vary: Cookie`. A page
  for an authenticated session (with or without a username), every HTML error page and the `405` are
  `Cache-Control: no-store` whatever the value.

| `error_pages`
| *Optional* boolean, *default `false`*. When `true`, an HTML-eligible gateway-originated error is
  answered with the portal template rendered as an error page, provided the request's `Accept`
  lists `text/html` explicitly with a quality above zero (`+*/*+` and `+text/*+` do not qualify). The
  status is unchanged, the page is anonymous and `no-store`, and a response relayed from an origin is
  never replaced. The eligible exits are listed under
  link:architecture/observability-and-errors.adoc#_error_contract[Error Contract].
|===

Every portal response carries `Content-Type: text/html; charset=utf-8`, `X-Content-Type-Options:
nosniff` and the fixed portal policy
`Content-Security-Policy: default-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`,
which replaces any `security_headers.content_security_policy` in either `header_modes` mode. The
other gateway-owned headers keep the global `security_headers` block. A portal response never sets a
cookie of its own.

*Session and links.* Without an active BFF runtime (no `oidc` block) every page renders anonymously
and carries no login or logout link. With one, a signed-in user is shown by the `preferred_username`
claim of the validated ID token, independently of `oidc.user_info.allowed_claims`. The login link is
`oidc.login.path?returnUrl=<url-encoded portal.path>` and the logout link is `oidc.logout.path`. Each
is present only when that path is declared. `oidc.logout.final_redirect: <portal.path>?notice=logged-out`
lands the verified logout on the portal with its signed-out notice. `notice` is a closed vocabulary
(`logged-out`) and its raw value is never echoed.

[[_endpoint_catalog]]
=== `endpoint.catalog`

An optional block on the `endpoint` of an endpoint file: the endpoint's entry on the
link:#_portal[portal] overview. The entry is active *exactly when the endpoint is enabled* after
placeholder resolution, so `ENDPOINT_<ID>_ENABLED` toggles the entry together with the endpoint's
routes. Without a `portal` block the catalog is resolved but never shown. Unknown keys are refused by
the schema.

[cols="1,3"]
|===
| Field | Meaning

| `title`
| *Mandatory* string, at least one character. The entry's display title, HTML-escaped when rendered.

| `description`
| *Optional* string. A one-line description rendered with the title, HTML-escaped. Omitted: `null`
  in the data model.

| `entry`
| *Mandatory* string. The link target: an origin-relative absolute path on the gateway's own origin
  (no scheme, authority or scheme-relative `//host`, which would make the portal an open redirect).
  The schema requires a single leading `/`, no `//` anywhere, no backslash and no control character.
  The validator also refuses, with `ApiSheriff-200` at `/endpoint/catalog/entry` and without echoing
  the value, a percent-encoded `/` or `\`, and a path part (before the first `?` or `#`) that the URL
  path review refuses. A query or fragment is allowed. Following the link is an ordinary request.

| `order`
| *Optional* integer. The sort key. Entries are listed by `order` ascending, an entry without `order`
  after every entry that declares one, then by `title`.
|===
